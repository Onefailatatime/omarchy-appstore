Herdr Core on Omarchy

Herdr Core (hc) is the free, open-source (Apache-2.0) headless server behind Herdr: it runs programs and coding agents in terminals that stay alive after you leave — from your shell, from an agent, or from the Herdr desktop app.

TL;DR

omarchy pkg add herdr-core
hc run --bg --name demo "echo hello from a terminal that outlives this shell"
hc ls            # see live terminals
hc read demo     # read output without attaching

Install herdr-core on Omarchy with one command — it takes under a minute. The Omarchy package installs /usr/bin/herdr-core and symlinks it as hc, the command you'll actually type. It needs only glibc and libgcc, builds for x86_64 and ARM64, and conflicts with the AUR's hc-bin and herdr-core-bin (same files, documented in the PKGBUILD).

You rarely need this package on its own: omarchy pkg add herdr-app already pulls herdr-core>=0.1.11 in. Install it standalone if you want the persistent-terminal server without the GUI window — e.g. on a headless box you drive from SSH.

Getting started (5 minutes)

1. Run something and walk away.

hc run cargo test streams output and waits. hc run --bg --name web bun dev starts it in the background and returns immediately, printing the terminal's address (like t1f). Close your viewer — the program keeps running. A foreground hc run that you leave waiting checks in after 180 seconds by default, printing the address so you can hc read it or wait again later.

2. The 3 things you need to know:

  • Attach, read, or take over — your choice. hc ls lists live terminals, hc attach web takes over a terminal (Ctrl+\ detaches), and hc read web --lines 100 reads output without disturbing the program. For a terminal you want to survive even if its program is lost, start it with hc run --keep — recovery brings back a fresh shell, never re-runs the task. A normal exit or an explicit kill still ends it.
  • Agents run agents. Give any agent hc --skill — it prints the full agent guide in one read: how to delegate, wait, report back, and clean up. Templates give an agent a command and a role: hc templates to list them, then e.g. hc run --bg --name review reviewer "Review src/x.rs. Read-only.", hc send review "Focus on the error path.", hc read review --lines 100. Agents started inside an hc terminal become its children — they report back with hc send, wait with hc wait --children all, and the parent gets notes when a child needs attention or ends. Children end with their parent unless started with --outlive-parent.
  • One core per machine, one list everywhere. hc machine add my-ssh-host --name box, then hc run --on box --cwd /srv/app cargo test runs on the remote — programs and files stay on that machine, while your local core folds its terminals into the same list (hc attach box/t3). Status comes from the program itself: an agent reports working/done/blocked/error through OSC 7501, the Program Status Protocol — the core stores what the program reports and never guesses from screen text. A program that doesn't report status has none. hc get review snapshots one terminal; hc events follows changes.

3. Config location.

~/.config/herdr-core/config.toml (or $XDG_CONFIG_HOME/herdr-core/config.toml). The one setting you'll touch first is the default shell — with no program, hc run --bg starts $SHELL (or /bin/sh):

shell = ["nu"]

Changes apply to the next new shell or --keep recovery, no restart needed. A bad setting reports a config error and a shell that can't start reports spawn_failed — recovery stays pending and retries, logging to core.log (config) or holder.log (spawn); it never silently falls back to another shell.

Core draws nothing. "Use it from your shell, an agent, or your own app." — README. If you want windows, panes, and an agents sidebar, that's the herdr-app package.

Common issues & fixes

hc update does nothing, or says updates are handled elsewhere

Fix: That's the packaging working as designed. The PKGBUILD notes: "A root-owned hc reports 'system package manager' and never updates itself." On Omarchy you update through the package manager, not hc update — the upstream hc update flow (which keeps running terminals across the update) only applies to the curl-installed binaries. Run your normal Omarchy package update instead; running terminals keep running.

New terminals fail with spawn_failed, or the core reports a config error

Fix: Check ~/.config/herdr-core/config.toml — the shell list must be an executable followed by separate arguments, no extra quoting, and it must be non-empty (e.g. shell = ["nu"]). A bad setting surfaces as a config error; a shell binary that can't start reports spawn_failed, with recovery pending and retrying. Read core.log (config problems) or holder.log (spawn problems) for the exact error — the core never silently falls back to a different shell, so what you configured is what failed.

A worker started on another machine shows up under the wrong parent in the Agents tree

Known open bug: issue #76 — with two cores registered to each other, a remote worker's parent keeps the incoming core ID instead of the machine alias, so the app's literal parent-address comparison misses the match and the worker doesn't nest under its real parent. Reproduced on Arch Linux (both hosts x86_64) with hc 0.1.16 / app 0.1.11. The reporter found no workaround. If your multi-machine Agents tree looks flat, check whether you're hitting this before rearranging your setup.

New tabs/spaces always start in the home folder after cd

This is a real bug — but Windows-only: issue #80 reports foreground.cwd never updating for Git Bash (MSYS2) shells on Windows, because MSYS2 keeps its POSIX cwd internally and never updates the Win32 process directory. On Omarchy/Linux, folder tracking follows the shell normally — if it doesn't, that's a different bug worth reporting with your shell named.

An agent shows no status — no Working/Blocked/Done, just a terminal

Nothing is broken: "Core stores what it reports. It does not guess from screen text or recognize agent brands. A program that does not report status has none." Status only exists if the program emits it via OSC 7501. Use hc get <terminal> to see the snapshot and confirm the program simply isn't reporting — then it's on the agent's side, not the core's.

Pairs well with / If you hate this, try

Pairs well with

  • herdr-app — the desktop window over this core; agents sidebar, spaces, and peek.
  • collie-bin — a phone web UI for the agents in your terminals, served over Tailscale.
  • Any coding agent that speaks OSC 7501 status (Claude Code, Codex CLI, and friends all live happily inside hc terminals).

If you hate this, try

  • tmux — the classic. Free, everywhere, sessions survive SSH disconnects and you can reattach from anywhere. What tmux doesn't give you: agent status, parent/child agent trees, multi-machine address routing (box/t3), or an OpenRPC API for building your own clients (hc schema prints it).
  • zellij — the modern middle ground: layouts and plugins, still TUI-only.

Verdict: Use hc when your terminals are agents — things with parents, children, statuses, and machines — that need to outlive your shell and be inspectable by other programs. Use tmux when you just want your own sessions to survive a dropped SSH connection.

herdr-core is free and open source — no paid product to undercut

herdr-core is free and Apache-2.0 — there's no paid product to undercut here. The comparison that matters is against the complexity of doing this yourself: hc run --bg, hc wait, and hc read replace a pile of nohup/redirect/poll scripting, and hc schema gives you an OpenRPC + JSON Schema API for building your own clients — hc connect even carries the protocol over stdin/stdout, including through SSH. The cost is one small server and a config file, versus zero new moving parts with tmux. Pick your trade.

Frequently asked questions

Does herdr-core work on Omarchy?

Yes — packaged as herdr-core (x86_64 + ARM64), depending only on glibc and libgcc. It conflicts with the AUR's hc-bin/herdr-core-bin, so pick one source.

Is herdr-core free?

Yes. Apache-2.0, herdrdev/herdr-core. No account, no paid tier; upstream's curl installer is free too.

Do I need it if I install the Herdr desktop app?

No — omarchy pkg add herdr-app depends on herdr-core>=0.1.11 and pulls it in. Install herdr-core alone only when you want the server without the GUI (headless boxes, SSH-driven workflows).

Do my programs survive closing my terminal?

Yes — that's the point. "Closing your viewer does not end the program." A reboot is different: kept terminals recover as fresh shells, not the old programs (--keep preserves the terminal; a normal exit or explicit kill still ends it).

How do I update it?

Through the Omarchy package manager. The packaged hc reports "system package manager" and won't self-update (documented in the PKGBUILD) — that's correct behavior, not an error.

How do agents talk to it?

hc --skill prints the agent guide in one read. Agents start workers with hc run --bg, coordinate with hc send / hc wait --children all, and report status to the core via OSC 7501 so the app can show Working/Blocked/Done/Idle.

What if I was using hc-bin from the AUR?

The packaged herdr-core conflicts with hc-bin and herdr-core-bin — remove the AUR package and install through the store command so the file ownership is consistent.
