omarchy-boot on Omarchy

omarchy-boot on Omarchy is the whole boot stack in one package: the Limine boot loader plus snapper, so every system update gets a snapshot you can boot into and roll back from.

TL;DR

omarchy pkg add omarchy-boot
omarchy snapshot create

That installs omarchy-boot (3.1 KB download, 0 B installed — it is a meta-package, version 1-1, MIT), which pulls in four pieces: limine, limine-mkinitcpio-hook, limine-snapper-sync, and snapper. omarchy snapshot create takes a snapshot of your system in about a second; if an update breaks something, you pick that snapshot in the Limine boot menu and restore it with omarchy snapshot restore. Limine has been the default boot loader since Omarchy 2.0, so on a standard install this stack is already there — the package exists to (re)install the whole thing in one command.

Getting started (5 minutes)

1. Understand the four pieces.

omarchy-boot itself installs nothing — it is a meta-package that guarantees the stack is present. limine is the boot loader that shows the "Omarchy Bootloader" menu. limine-mkinitcpio-hook rebuilds your boot entries whenever the kernel or initramfs changes. limine-snapper-sync keeps the snapshot entries in that menu in step with snapper. snapper is the tool that actually takes Btrfs snapshots of your root filesystem. Omarchy stores its system on Btrfs, so a snapshot takes about a second and starts out using almost no extra disk space.

2. Make a snapshot before you change anything.

Open a terminal (Super + Enter) and run:

omarchy snapshot create

It prints two lines — a green "Create system snapshot" and "Snapshots can be selected during boot" — and finishes in about a second. The snapshot's description is your Omarchy version. You do not have to do this before every update: omarchy update takes a snapshot automatically before it changes any package. Do it yourself before installing, removing, or changing system packages by hand, since a plain pacman command takes no snapshot. Omarchy keeps the 5 most recent snapshots and discards older ones.

3. Three things worth knowing before you ever need a rollback:

  • Boot into a snapshot from the menu. Reboot, and at the "Omarchy Bootloader" menu press any key to stop the ~5-second countdown. Open the Snapshots folder, pick the snapshot by its date (newest first; the Omarchy version at the time shows at the bottom of the screen), open it, and boot its linux-omarchy entry. Type your disk password as usual. The desktop looks the same as a normal boot — the snapshot is read-only, with a temporary layer in memory on top, so system changes you make inside it are lost at the next reboot while files in your home folder stay.
  • Restore it for good. Once you have confirmed the snapshot works, run omarchy snapshot restore in a terminal. It shows the snapshot's number, date, and description, asks "Restore snapshot N (method: replace)?" — type r — then asks for a description for a backup of your current system (press Enter to keep the default "backup before restore"). It finishes in a second or two and asks "Restore complete. Reboot now?" Press Enter to reboot into the restored system. Changed your mind later? That backup snapshot sits at the top of the Snapshots list — boot it and restore it the same way.
  • A restore rolls back the system, not your home. It restores programs, system settings in /etc, and the package database. Your files and ~/.config stay as they are, so if you roll back to an older app version that already rewrote its settings in a newer format, you sort that out by hand. And Omarchy's record of which migrations already ran lives in your home folder, so it survives the restore — migrations that ran after the snapshot stay marked as done, and the next omarchy update will not run them again.

Common issues & fixes

The computer booted the normal system before you could pick a snapshot

The Limine countdown is about five seconds, and the menu boots the default entry when it runs out.

Fix: Reboot and press any key as soon as the menu shows — any key stops the countdown. (Documented in the Starry Hope walkthrough, Omarchy 4.0.4; not reproduced on a live machine.) (Starry Hope: Roll Back Omarchy with Snapshots and Limine)

Snapper commands fail inside a booted snapshot with an "IO Error"

In a booted snapshot, root is the temporary overlay, not a Btrfs subvolume, so sudo snapper -c root list and friends cannot work there.

Fix: Make new snapshots and manage old ones from the normal system: restore first, or reboot to linux-omarchy. (Documented in the Starry Hope walkthrough; not reproduced on a live machine.) (Starry Hope)

A deleted snapshot is still listed in the boot menu

The boot menu entries are generated from snapper's list, so a deleted snapshot lingers in the menu until the entries are rebuilt.

Fix: List snapshots with sudo snapper -c root list, delete one by number with sudo snapper -c root delete 17, then rebuild the menu with sudo limine-snapper-sync. (Documented in the Starry Hope walkthrough; not reproduced on a live machine.) (Starry Hope)

You turned on Direct Boot and can no longer reach your snapshots

Setup > Direct Boot adds an EFI entry that boots straight to the disk password screen, skipping the Limine menu.

Fix: To reach a snapshot, pick Limine from your firmware's boot menu (BIOS/UEFI boot picker), or run Setup > Direct Boot again to turn it off and boot through Limine as before. Note the setup refuses to run on American Megatrends and Apple firmware, so on those machines the Limine menu stays. (Documented in the Omarchy manual; not reproduced on a live machine.) (Omarchy Manual: System snapshots)

You restored a snapshot and something an earlier update had set up is still missing

That is the migrations record, not a failed restore. Omarchy's record of which migrations already ran lives in your home directory, so it survives the restore, and the next omarchy update will not re-run migrations that ran after the snapshot was taken.

Fix: Re-run the missing setup step by hand, or check the Omarchy release notes for what that migration did. (Documented in the Omarchy manual; not reproduced on a live machine.) (Omarchy Manual: System snapshots)

Pairs well with / If you hate this, try

Pairs well with

  • omarchy update (it snapshots automatically before every update, so the two are one safety net), limine-snapper-sync and limine-mkinitcpio-hook (the other two pieces of the stack, also in the store), and a real backup of your home folder — snapshots cover the system, not your files.

If you hate this, try

  • If you hate Limine: GRUB and systemd-boot are the other Linux boot loaders, but snapshots from the boot menu do not work on either — that feature is Limine-only on Omarchy. If you want snapshot-style rollback without Limine, Timeshift is a separate GUI tool for Btrfs/rsync snapshots, but it does not integrate with the Omarchy boot menu.

omarchy-boot is free, and it is the safety net built into Omarchy

There is nothing to pay for here. omarchy-boot is free and MIT licensed, and it replaces no paid software — it is the safety net built into Omarchy itself. The thing it saves you from paying for is your own time: without bootable snapshots, a broken update means an afternoon of reinstalling or debugging from a live USB. With them, it means one reboot and one command.

How to switch from GRUB or systemd-boot to Limine + snapshots (~15 minutes plus a reboot)

  1. Check what you boot with now: if your Omarchy install predates 2.0 or you switched boot loaders yourself, you are on GRUB or systemd-boot and snapshots from the boot menu will not work.
  2. Install the stack: run omarchy pkg add omarchy-boot to pull in limine, limine-mkinitcpio-hook, limine-snapper-sync, and snapper, then follow the Omarchy installer's Limine setup to point your firmware at Limine. This step is the least documented part of the switch — verify it on a real machine before treating it as a recipe.
  3. Take your first snapshot: run omarchy snapshot create and confirm the new entry appears under Snapshots in the Limine menu on the next boot.
  4. What doesn't transfer: your old GRUB/systemd-boot menu entries and any custom boot configuration have to be recreated in Limine's config (/boot/limine.conf, managed via /etc/default/limine).
  5. Time estimate: about 15 minutes plus a reboot, not counting any firmware fiddling.

Frequently asked questions

Do I need to install omarchy-boot if Limine is already my boot loader?

Probably not — Limine has been the default since Omarchy 2.0, and on a standard install the whole stack is already there. The package is the one-command way to (re)install it if pieces were removed. This is unverified on a live machine; it is an open item on the checklist.

Does omarchy-boot work on GRUB or systemd-boot installs?

No. Snapshots from the boot menu only work with Limine, which has been the default since Omarchy 2.0. If you are on GRUB or systemd-boot, you need to switch boot loaders first.

Does a restore bring back files I deleted from my home folder?

No. A restore covers the root filesystem only — programs, /etc, and the package database. Your home folder, including ~/.config, is untouched. Back up personal files separately.

How many snapshots does Omarchy keep?

Five. Omarchy's snapper policy keeps the 5 most recent snapshots made by an update or by you, and deletes older ones right after each new one. Snapshots made with a plain sudo snapper -c root create do not count toward the five, and neither does the "backup before restore" snapshot.

How do I list or delete snapshots?

Run sudo snapper -c root list to see them with their numbers and descriptions, and sudo snapper -c root delete <number> to remove one. If the deleted entry is still in the boot menu afterwards, run sudo limine-snapper-sync to rebuild it.

What happens if I run sudo pacman -Syu directly?

Omarchy blocks a bare sudo pacman -Syu — the guard stops the upgrade and points you to omarchy update, because a direct upgrade skips the snapshot and the migrations. Always update with omarchy update.
