apple-t2-audio-config on Omarchy

apple-t2-audio-config is a tiny (5 KB) set of ALSA UCM configuration files that tells Linux how to talk to the speakers, headphone jack, and microphones on an Apple T2 Mac — without it, a T2 Mac running Omarchy has no working built-in audio at all.

TL;DR

omarchy pkg add apple-t2-audio-config
sudo reboot

It takes under a minute (5 KB download, 5.1 KB installed). Then reboot onto the linux-t2 kernel — the config only takes effect on a T2-patched kernel, and sound will not work until you do.

Already installed? If you installed Omarchy on a T2 Mac through the normal installer, you probably already have this: the Omarchy manual says the installer automatically sets up the patched linux-t2 kernel, "the T2 audio configuration," the Broadcom Wi-Fi/Bluetooth firmware, and fan control via t2fanrd on T2 models. Check first with pacman -Qi apple-t2-audio-config — this guide is for the people who installed manually, reinstalled, or are missing sound after the fact.

Don't follow the Fedora guide. The store links the project site to kaiT2en's GitHub repo (kaiT2en/KaiT2en-Fedora), which brings T2 support to stock Fedora using DKMS kernel modules. That is the Fedora project, not the Omarchy one. On Omarchy you do not run their installer — the Arch apple-t2-audio-config package (UCM files only, from the arch-mact2 lineage) is all you need, and the kernel side comes from the separate linux-t2 package.

Getting started (5 minutes)

1. Install and reboot onto the linux-t2 kernel.

Run the install command above, then reboot. This package is configuration only — it contains no driver and no kernel. The actual audio driver is apple-bce (via the t2bce audio driver) inside the linux-t2 kernel, and the UCM files in this package tell ALSA/PipeWire how to use it. After rebooting, confirm you're on the T2 kernel:

uname -r

You should see a kernel name containing t2. If you booted the stock Arch kernel instead, the T2 audio hardware simply isn't there — no config file can fix that. (Unverified on Omarchy: confirm the exact uname -r output on a real T2 install.)

2. Confirm the driver and device are present.

The t2linux wiki says the apple-bce driver must be loaded and the audio device should appear as AppleT2xN:

lsmod | grep apple_bce
aplay -l

If apple-bce isn't loaded or nothing T2 shows up in aplay -l, the problem is below this package — the kernel or the driver, not the config. See "No sound at all" in Common issues.

3. Pick the T2 output and test the speakers.

Open Omarchy's audio settings (or pavucontrol / wpctl status) and select the T2 speakers as the output device. Then test:

speaker-test -c 2

You should hear a tone alternating left/right. Stop it with Ctrl+C. On T2 Macs the headphone jack and the internal speakers are separate devices, not one device that auto-switches — if sound comes out of the wrong place, you picked the wrong output, not a broken driver (see "Sound comes out of the wrong device" below).

4. Test the microphone.

Record five seconds and play it back:

arecord -d 5 -f cd test.wav && aplay test.wav

If you hear yourself, you're done — the whole setup took five minutes. If the mic is silent or barely audible, that's the known weak spot of T2 audio on Linux, not a mistake you made: see "Speakers work but the internal mic doesn't" below.

The 3 things you need to know:

  • This package is config, not a driver. It ships UCM (Use Case Manager) profiles — text files that describe the T2 audio hardware to ALSA so PipeWire can present "Speakers," "Headphones," and "Internal Microphone" as real devices. The driver lives in the linux-t2 kernel. Installing this package without the T2 kernel does nothing.
  • Reboot after installing. UCM profiles are read when the audio stack starts up against the hardware. Installing the files while running is not enough — reboot onto linux-t2 so ALSA picks them up with the driver.
  • Where the config lives. Run pacman -Ql apple-t2-audio-config to see exactly what it installed (expected: UCM profile files under /usr/share/alsa/ucm2/, the standard location ALSA reads UCM2 configs from). Don't edit the files under /usr/share/ directly — if you need to override something, copy the relevant profile to /etc/alsa/ucm2/ and edit the copy, since /etc takes priority and survives package updates. (Unverified: confirm the installed paths with pacman -Ql on a real install.)

Config location.

The package's files live under /usr/share/alsa/ucm2/ (confirm with pacman -Ql apple-t2-audio-config). There is no user config file and no app to open — this package has no commands, no window, and no settings of its own. Your audio settings live in PipeWire/WirePlumber, and per-user volume/device choices live in your desktop's sound settings.

Common issues & fixes

All of these come from the t2linux wiki's audio configuration guide — they are the project's documented failure modes, not guesses. Each one is still marked for on-machine confirmation in the checklist above.

No sound at all after installing

You installed the package and rebooted, but there is no audio device at all — no speakers, no mic, nothing in settings.

Fix: Work down the stack, because this package is the top layer, not the bottom. First, confirm you're actually on the T2 kernel (uname -r should contain t2) — if you booted the stock Arch kernel, the t2bce driver isn't present and no config will help. Second, check the driver is loaded (lsmod | grep apple_bce) and the device shows as AppleT2xN — the wiki says if you only see AppleT2 without the x, your driver is out of date, and if there's no output at all, the BCE module isn't set up. Third, check the kernel parameters the wiki requires are present:

cat /proc/cmdline

They must include intel_iommu=on iommu=pt pcie_ports=compat — without them, the audio hardware can't communicate properly. If they're missing, add them to your bootloader config and reboot. Finally, confirm the config files actually landed (pacman -Ql apple-t2-audio-config should list UCM files) and that the alsa-ucm-conf dependency installed with it.

Speakers work but the internal mic doesn't (or is barely audible)

Output is fine, but the internal microphone records silence or is so quiet it's unusable. This is the single most-reported T2 audio problem, and the wiki is blunt about it: the internal mics "often require additional Digital Signal Processing (DSP) configuration to function optimally," and "some users may still experience issues with audio input and might need to use an external microphone as a workaround."

Fix: First, rule out the simple stuff: check the mic isn't muted and the input volume is up in your sound settings or alsamixer (F4 for capture devices), and confirm the right input is selected — the internal mic and the headphone-jack mic are separate inputs. If the level is just low, the wiki's documented paths are EasyEffects with PipeWire (its Autogain plugin and pre-made presets, tested on MacBook Pro 15,1) or the PipeWire filterchain DSP configs from the t2-apple-audio-dsp repository. If it still doesn't work, use an external USB microphone as the fallback — the wiki presents that as a legitimate outcome, not a failure. (Unverified on Omarchy: whether the mic works out of the box with just this package, or needs the DSP step, on current installs.)

Sound comes out of the wrong device / headphones don't switch automatically

You plug in headphones and sound keeps coming from the speakers, or vice versa. On T2 Macs the headphone jack and the internal speakers are separate audio devices, so the auto-switching you expect from a normal laptop doesn't happen by itself.

Fix: Set the device you want as the default sink explicitly — in your desktop's sound settings, pavucontrol, pactl, or wpctl. The wiki specifically recommends PipeWire over PulseAudio here, because PipeWire's device switching lets you select the speakers as the output even while headphones are plugged in. To make headphones switch automatically when plugged in, set them as the default sink in your desktop environment's settings app. (Unverified: confirm the exact device names PipeWire shows for the T2 speakers vs. headphone jack on a real install.)

Audio broke after a kernel update

Sound was working, you updated, and now it's gone — or you're back to silence after a reboot.

Fix: This is almost always a kernel mismatch, not a config problem. After a linux-t2 update you must reboot onto the new T2 kernel; if the bootloader entry still points at the old kernel — or you accidentally booted the stock Arch kernel — the t2bce driver and this package's UCM profiles have nothing to attach to. Check uname -r first: if there's no t2 in it, reboot and pick the linux-t2 entry. If you are on the new T2 kernel and still have no sound, check pacman -Qi apple-t2-audio-config is still installed (a partial update can leave it behind) and re-run the checks in "No sound at all" above. (Unverified on Omarchy: this is the standard T2 failure pattern from the wiki's prerequisites, not a reproduced Omarchy report — confirm the exact behavior after a real linux-t2 update.)

Sound is thin, tinny, or much quieter than macOS

Audio plays, but it sounds flat and quiet compared to the same machine in macOS. Apple's speakers are specially tuned, and the plain UCM config doesn't reproduce macOS's DSP.

Fix: This package gives you working speakers, not macOS-quality speakers. The wiki documents model-specific DSP configurations in the t2-apple-audio-dsp repository — including an experimental one for the MacBook Pro 16" (2019) with 6 speakers — that improve quality significantly. The warning matters: each Mac model needs its own DSP settings, and using another model's configuration could damage your speakers. Only use a DSP profile made for your exact model. For a quick volume lift without DSP, PipeWire users can try EasyEffects; the wiki also notes some desktops let you "raise maximum volume" beyond 100%. (Unverified on Omarchy: no DSP profile has been tested from this guide.)

Pairs well with / If you hate this, try

Pairs well with

  • linux-t2 — the patched kernel this config is useless without; if sound is missing, the kernel is the first thing to check. apple-bcm-firmware-fetcher — pulls the Broadcom Wi-Fi/Bluetooth firmware out of macOS; the other half of making a T2 Mac fully usable (the Omarchy installer sets both up automatically on T2 models). t2fanrd — the fan-control daemon for T2 Macs; same story, same installer bundle, same "you probably already have it" caveat. And easyeffects (in the store) if your mic needs the DSP/Autogain lift the wiki describes.

If you hate this, try

  • Installing the config manually from the t2-better-audio repository (kekrby's original config files, which the wiki points to) — same files, more steps, no package manager tracking them. Or a USB audio interface / USB DAC, which bypasses the T2 audio hardware entirely and works with the stock kernel — the pragmatic escape hatch if the internal speakers and mic fight you for more than an evening.

It rescues hardware you already own

There is no paid version of this — it's a 5 KB config package, MIT-licensed, that replaces nothing you could buy. The honest framing is the reverse: it rescues hardware you already own. A 2018–2020 Intel Mac is officially obsolete — macOS 26 "Tahoe" ended support for T2 Intel Macs — and without this config plus the linux-t2 kernel, that machine's speakers and mic are dead weight under Linux. Five kilobytes of config is what stands between a still-powerful laptop and e-waste. What you give up versus macOS: the tuned DSP sound quality (fixable per-model, with care) and the possibility that the internal mic needs extra work. What you keep: the machine, the speakers, the mic, and $0 spent.

Frequently asked questions

Does apple-t2-audio-config work on Omarchy?

Yes. It's in the official Omarchy repo as apple-t2-audio-config (version 0.4.r21.ga973d53-2, built Nov 16, 2026) and installs with one command: omarchy pkg add apple-t2-audio-config. But it only works on a T2 Mac running the linux-t2 kernel — it's configuration for that kernel's t2bce audio driver, not a driver itself. On a non-T2 machine it does nothing.

Do I even need to install it?

Probably not, if you installed Omarchy on a T2 Mac with the normal installer — the Omarchy manual says the installer sets up the T2 audio configuration automatically on T2 models. Check with pacman -Qi apple-t2-audio-config before installing. You need this guide if sound is missing, if you installed manually, or if you reinstalled and the audio setup didn't come along.

Is apple-t2-audio-config really free?

Yes. MIT-licensed, no paid tier, no account. The Omarchy package is 5 KB to download and 5.1 KB installed, with one dependency (alsa-ucm-conf), which Omarchy installs for you.

Why does the project site point to a Fedora repo?

The store lists kaiT2en's GitHub repo (kaiT2en/KaiT2en-Fedora), a project that brings T2 support to stock Fedora using DKMS modules. That's the Fedora project. The Omarchy package is the Arch apple-t2-audio-config — just the ALSA UCM files — and on Omarchy you should not follow the Fedora install guide. The kernel side comes from the separate linux-t2 package.

Why is there no app to open after installing?

Because there's nothing to launch — this package is a set of config files, not a program. It has no commands and no window. You verify it worked by checking your sound settings: the T2 speakers and mic should appear as devices. Run pacman -Ql apple-t2-audio-config to see the files it installed.

Will this make my MacBook sound as good as it did on macOS?

Not by itself. It gives you working speakers; macOS-quality sound needs the model-specific DSP configs from the t2-apple-audio-dsp repository, and the internal mic may need DSP work too. Never use another model's DSP profile — the t2linux wiki warns it could damage your speakers.

Does it work on Apple Silicon (M-series) Macs?

No. This is for Intel Macs with the T2 security chip (2018–2020 models). Apple Silicon audio is a completely different subsystem, and Omarchy doesn't support installing on M-series Macs at this time.

How do I update it?

On Omarchy, omarchy-update upgrades it with the rest of the system — then reboot so the new config loads with the kernel. To remove it: omarchy pkg drop apple-t2-audio-config (sound will stop working until you reinstall it or hand-install the config another way).
