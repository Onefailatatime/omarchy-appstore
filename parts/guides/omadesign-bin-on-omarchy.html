Omadesign on Omarchy

Omadesign is the free, MIT-licensed native Linux creative suite — vector design, layout, pixel painting, RAW photo development, and motion in one Rust app — that inherits your Omarchy theme and font on launch, and it now installs with one command from Omarchy's own package repo as omadesign-bin.

TL;DR

omarchy pkg add omadesign-bin

Takes about 2 minutes: you get the vendor 0.6.3 binary repackaged to /usr/bin/omadesign (it conflicts with the old source package name omadesign, which never shipped). Free forever (MIT). Every editing feature works offline with no account; cloud features (shared projects, team review) need a sign-in, and no pricing is published for them.

The honest caveat up front: the package is fresh. It was merged into omarchy-pkgs on October 11, 2026, and new packages land on the edge ring first, only reaching stable on the next release train — if omarchy pkg add omadesign-bin says "target not found," you're on stable and should wait for promotion or use the curl route (curl -fsSL https://omadesign.app/install | sh, which unpacks into ~/.local, no sudo). Second caveat: this is alpha software that moves fast (0.6.0 to 0.6.3 in one month), and this guide is written against 0.6.3.

Getting started (5 minutes)

1. Install.

Run the command above in a terminal. You get the 0.6.3 binary at /usr/bin/omadesign, a desktop entry, an SVG icon, MIME registrations (so .oma files open in it), and man pages — no ~/.local/bin PATH dance, since it's a system install. The package also ships the agent skills and plugin files under /usr/share/omadesign/.

2. First launch.

Hit Super + Space and type "oma", or run omadesign. You land on a welcome screen that scans your home directory for existing .oma projects (skipping hidden folders, Trash, and symlinks) and offers +Vector and +Layout buttons that open the template picker. The window already wears your Omarchy palette and font — there is no light/dark toggle because it mirrors whatever theme is active.

3. The 3 things you need to know:

  • Modes, not separate apps. Centered buttons across the top switch between Vector, Raster, Layout, Photo, Motion, and Agent — all on one document and one layer stack. Press R for rectangle, P for pen, T for type, B for brush, C for crop. F1 opens the full shortcut list; Ctrl + / toggles a shortcut overlay for the current tool. (Confirm shortcuts on-machine — this is from the site guide's research, not a live test.)
  • It opens and exports the files you already have. Import covers PSD/PSB, GIMP XCF, PDF, Illustrator (PDF-compatible), OpenRaster, SVG, and camera RAW (DNG, CR2/CR3, NEF, ARW, RAF). Export covers layered PSD, PDF, OpenRaster, 16-bit PNG/TIFF, JPEG, SVG, animated SVG, Lottie, and responsive HTML. The limits are real and documented: PSD text and smart objects come in as flattened pixels, there is no writer for AI or XCF, and PDF export turns text into outlines. Install ghostscript (an optional dependency of the package) for EPS and PostScript-based Illustrator import.
  • Updates: check which path you're on. From the curl install, updates happen in-app via Omadesign > About > Update, which reruns the official installer and restarts with your documents open. From the omadesign-bin package, updates should arrive with your normal package updates — confirm on-machine whether the in-app updater is disabled in the packaged build or fights with it.

4. Where its config lives.

Preferences: ~/.config/omadesign/. Crash-recovery swap files: ~/.local/share/omadesign/<id>.oma.swp (written after about a second idle, deleted on save). Theme is read on launch from ~/.local/state/omarchy/current/theme/colors.toml, falling back to ~/.config/omarchy/themes/<current>/colors.toml, then a built-in Catppuccin. Font: whatever omarchy font current returns, then fontconfig sans-serif; override with OMADESIGN_FONT=/path/to/font.ttf. Projects are plain folders — a folder counts as a project when it holds .omacolors, .omatype, or an .omabrand/ directory. Photo edits sit next to the original as photo.jpg.omaphoto.

5. Omarchy-specific note.

The theme/font integration is the whole point of this app on Omarchy: it's the only design suite here that repaints when you switch themes (a file watcher for that shipped in 0.6.0). Binaries are linked against glibc 2.35, so they run on Asahi Omarchy, current Arch ARM, and anything newer — the package builds for both x86_64 and aarch64.

6. CLI pro tip.

omadesign --inspect artwork.psd prints a file's structure without opening the UI, and omadesign --convert artwork.afdesign --output artwork.oma converts between supported formats. omadesign --agent-skill prints a ready-made skill file describing the CLI and document format — drop it in .claude/skills/ and Claude Code can batch-convert and inspect your files without you opening the app. (From the site guide's research; confirm flag names on-machine.)

Common issues & fixes

omarchy pkg add omadesign-bin says "target not found"

Fix: You're on the stable channel and the package hasn't been promoted yet. It was merged October 11, 2026 and published to the edge ring; stable gets it with the next Omarchy release train. Until then, use the curl one-liner (curl -fsSL https://omadesign.app/install | sh) into ~/.local, or download the tarball and checksum from the GitHub releases page, verify with sha256sum -c, extract, and run the install.sh inside. There is no AUR package — the maintainer declined that request (issue #73). If the package has since reached stable, this section is stale; check before relying on it.

You switch Omarchy themes and Omadesign keeps the old colors

Fix: Builds before 0.6.0 read the palette once at startup and cached it (issue #133). A file watcher shipped in 0.6.0. Check Omadesign > About — if you're on 0.5.x, update. On a current build a theme switch repaints live; if it still doesn't, confirm ~/.local/state/omarchy/current/theme/colors.toml exists, since that's the file it watches.

Ctrl + C / Ctrl + V do nothing, and fcitx5 can't type CJK into a text box on Hyprland

Fix: Before 0.6.2 the app never activated the Wayland text-input protocol, so the input method never received keystrokes and the clipboard sat on the wrong path (issue #83). Fixed in 0.6.2 — verified by the maintainer under Sway with fcitx5 and Rime; the original report was on Hyprland 0.56. Update through your package channel or the in-app updater. Omarchy ships fcitx5 by default, so this one bit Omarchy users specifically.

Typing and brush strokes lag badly, or motion playback stutters on a big comp

Fix: Two separate things. Motion playback on complex compositions was fixed upstream at the end of September 2026 (issue #177) — update first. The lag is hardware: the maintainer's own benchmark ran the same build on three machines, and a 4-core AMD thin client with under 6 GB RAM saw 90 ms median keystroke latency with half-second stalls, while an 8 GB Intel laptop sat at 35 ms and an M1 Pro at 21 ms (issue #158). Provisional guidance: 8 GB RAM minimum, 16 GB recommended, and four cores isn't enough. A dedicated GPU is not needed — AI features (background removal, upscaling) run on the CPU.

Affinity files won't open

Fix: Affinity import goes through an optional GPL-licensed bridge that is not bundled. Run ./scripts/setup-affinity-import.sh from a source checkout once — it needs Inkscape's Python modules plus the Python zstandard, Pillow, and numpy packages. Even then, adjustments, live effects, and edit history don't survive, and multi-spread documents can fail.

  • inkscape plus gimp plus darktable — the three separate tools Omadesign is trying to replace. All are one omarchy pkg add away, all are mature, none follow your theme.

Omadesign is a free alternative to Adobe Creative Cloud

Omadesign is a free alternative to Adobe Creative Cloud. What you give up, honestly: maturity (this is alpha, and a one-person project), PSD text and smart-object fidelity on import (they flatten), any AI/XCF export, and the plugin ecosystem decades of Photoshop/Illustrator built. What you keep: vector, layout, pixel painting, RAW development, and motion in a single native Linux window that matches your desktop — free forever under the MIT license, no subscription, no account for local work.

How to switch from Adobe (~15 minutes per project)

  1. Export from Adobe: save working files as PSD/PSB (layered), AI as PDF-compatible, and photos as DNG/RAW. Omadesign imports all of these.
  2. Import into Omadesign: open the files directly — they'll convert to editable .oma projects, with conversion notes explaining what changed.
  3. What doesn't transfer: PSD text layers and smart objects flatten on import; multi-spread layouts and adjustment history need rebuilding; no scripted actions/plugins.
  4. Time estimate: ~15 minutes per project to import and check fidelity; budget a day to rebuild the templates you rely on.

Frequently asked questions

Does Omadesign work on Omarchy?

Yes — it was built for it. The UI reads your Omarchy theme colors and font on launch and repaints when you switch themes. It runs natively on Wayland under Hyprland, on both x86_64 and Apple Silicon via Asahi. Expect a 4-core or sub-8 GB machine to feel slow (see the benchmark in Common issues).

Is Omadesign free?

Completely, under the MIT license. No trial, no paid tier, no account for local work. Cloud sharing features need a sign-in but there is no published pricing.

How do I install it — the curl script or the package?

The package (omarchy pkg add omadesign-bin) is the current official path and installs system-wide to /usr/bin/omadesign. The curl one-liner still works and installs into ~/.local without sudo. If the package isn't on your channel yet (edge-first promotion), use the curl route.

Omadesign vs Inkscape — which should I pick?

Inkscape if you need a specific SVG feature or you ship files to people on other tools — it's the safer bet for anything client-facing. Omadesign if you want raster, photo, and motion in the same window and prefer a native GUI over GTK3. Many people will keep both installed.

How do I update Omadesign?

From the package: normal package updates. From the curl install: Omadesign > About > Update reruns the official installer and restarts with your documents open. Confirm on-machine whether the in-app updater is disabled in the packaged build.

My theme change didn't apply. Is that a bug?

Only on builds before 0.6.0 — check About for the version and update. On 0.6.x, confirm ~/.local/state/omarchy/current/theme/colors.toml exists, since that's the file it watches.
