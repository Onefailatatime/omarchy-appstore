Notion on Omarchy

Notion is the all-in-one workspace — docs, wikis, databases, tasks, and calendars in one app — and this is the official Notion desktop app, repackaged by David Heinemeier Hansson himself from Notion's own Linux Flatpak into a native Omarchy package, with a launcher that forces native Wayland rendering on Omarchy.

TL;DR

omarchy pkg add notion-desktop

Install the official Notion desktop app on Omarchy with one command. 98.9 MB download, 394 MB installed, version 7.41.1-1. That's a full Chromium runtime under the hood — the price of an Electron app. Launch from the app launcher or notion-desktop in a terminal, sign in with your Notion account (email magic link), and your workspace syncs down.

Getting started (5 minutes)

1. First launch.

Open Notion from the launcher (or run notion-desktop). It asks you to sign in — enter your email and Notion sends a magic link / code; complete it in the browser and the app picks up your session (confirm the exact flow on Omarchy during the verify pass). Pick your workspace and you're in: sidebar on the left, your pages, and the "New page" button.

2. The 3 things you need to know:

  • It's cloud-first. Your data lives on Notion's servers, not on your machine — every page syncs, collaboration is live, and you need a network connection. If you want notes that are yours even when offline, that's what Slap Notes (local-first, also in the store) is for.
  • The launcher already handles Wayland. The package's launcher script passes --ozone-platform=wayland so the app renders natively instead of falling back to blurry XWayland on scaled displays — no flags needed on a stock Omarchy box. If you ever need to override it (or pass other Chromium flags), each line of ~/.config/notion-desktop-flags.conf becomes an extra argument, and your own --ozone-platform choice wins over the default.
  • The window's app id is notion. The package is built from Notion's Flatpak, whose id is com.notion.app.desktop.notion — but outside a Flatpak the window reports notion, and the .desktop entry sets StartupWMClass=notion to match. So Hyprland rules target notion: 
    windowrule = float, class:^(notion)$

3. Config location.

Electron apps keep state under ~/.config/Notion (unverified — confirm on the box; the flags file ~/.config/notion-desktop-flags.conf is confirmed by the launcher script). The actual app binary lives at /opt/notion-desktop/Notion if you ever need to point something at it directly.

Common issues & fixes

All sourced from the Omarchy packaging (PKGBUILD, launcher script, upstream tracking) and Notion's public product docs. Nothing below was reproduced on Omarchy — confirm each fix on-machine before relying on it.

The app looks blurry on a scaled (HiDPI) display

The package launcher forces native Wayland (--ozone-platform=wayland) precisely because Chromium's auto-detection falls back to XWayland "often enough to matter," per the launcher's own comments.

Fix: If it's blurry anyway, something overrode the platform: check ~/.config/notion-desktop-flags.conf for a conflicting --ozone-platform line (user-set platform flags win), remove it, and relaunch. If native Wayland itself glitches, force XWayland deliberately by adding --ozone-platform=x11 to that flags file instead of guessing. (Source: notion-desktop-launcher.sh in omacom/omarchy-pkgs.)

Window rules or dock pinning don't match the app

The Flatpak id (com.notion.app.desktop.notion) is the .desktop filename, but the window's app id is notion.

Fix: The package's PKGBUILD rewrites the entry to Exec=notion-desktop %U and adds StartupWMClass=notion for exactly this reason — write Hyprland rules against class:^(notion)$, verified with hyprctl clients. If you pinned the app before this package existed (old unofficial wrappers), unpin and re-pin.

Notion needs an account and a connection — nothing works offline the way local notes apps do

That's the product, not a bug: Notion is a cloud workspace; the Linux app is a full client of it, not a sync engine you can point at local files.

Fix: The free plan covers unlimited pages and blocks for individuals, so the install costs nothing — paid Plus/Business tiers are per-user on notion.com/pricing. If your notes must work on a plane, pair Notion with a local-first app (Slap Notes) rather than fighting this.

394 MB installed feels enormous for a notes app

It is — that's a bundled Chromium plus Notion's app bundle.

Fix: The package is built with maximum zstd compression specifically to keep the download at 98.9 MB (noted in the PKGBUILD). If disk space matters and you only need Notion occasionally, the web app at notion.com is the same product with zero install; the desktop app's wins are the tray, global shortcuts, and not living in a browser tab.

The package lags a Notion release you just read about

Updates are automatic but deliberate: a sync script (.omarchy/upstream.sh) polls Notion's own OSTree repo, and a version only ships when both the x86_64 and aarch64 commits agree — if Notion releases one architecture first, the package waits rather than shipping a half-release.

Fix: Maintainer is David Heinemeier Hansson, so it tracks upstream closely; give it a day or two.

Notion is free for individuals — the desktop app costs $0

Notion is free for individuals. What you give up: nothing to start — the free plan covers unlimited pages and blocks for individuals, and the app install itself costs nothing. What costs money: the Plus/Business tiers (per-user pricing on notion.com/pricing) — that's for teams that need admin controls and collaboration at scale. What you keep: the whole workspace — docs, wikis, databases, tasks, calendars — in an official native Linux client with native Wayland rendering.

How to switch to the desktop client (~5 minutes)

  1. If you already use Notion in the browser: there is nothing to export — the desktop app is the same product. Install it, sign in with the same email magic link, and your entire workspace syncs down.
  2. Set up window rules: add windowrule = float, class:^(notion)$ to your Hyprland config if you want it floating, and confirm with hyprctl clients that the app id is notion.
  3. Check scaling: the launcher forces native Wayland, so text should be sharp on a HiDPI display. If it's blurry, check ~/.config/notion-desktop-flags.conf for a conflicting --ozone-platform line (see Common issues).
  4. Time estimate: ~5 minutes from install to a signed-in, synced workspace. Your data already lives on Notion's servers — the client is just a new window onto it.

Frequently asked questions

Does Notion work on Omarchy?

Yes — this package repackages Notion's official Linux Flatpak (built from Notion's own OSTree repository at app.linux-packages.notion.com) as a native Arch package, for both x86_64 and aarch64. Install with omarchy pkg add notion-desktop.

Is Notion free?

The app install is free and Notion has a free plan (unlimited pages/blocks for individuals). Plus and Business are paid per user — check notion.com/pricing for current numbers. License of the app itself is proprietary ("custom" — Notion ships no license text; terms at notion.com/terms).

Does the Notion desktop app work offline on Linux?

Notion is cloud-first: your workspace syncs from Notion's servers, and you need a connection. Treat it as an online app, not a local notes store. (Confirm exact offline behavior on Omarchy during the verify pass.)

Why is the download 99 MB and the install 394 MB?

It's an Electron app — a full Chromium runtime plus the Notion bundle. The download stays small because the package is compressed with maximum zstd; the install size is the real footprint.

How do I uninstall it cleanly?

omarchy pkg drop notion-desktop. Electron state under ~/.config/Notion is left behind (unverified path — confirm during verify pass); remove it if you want a fully clean slate.
