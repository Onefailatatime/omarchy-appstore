Devin CLI on Omarchy

Devin CLI on Omarchy is Cognition’s terminal coding agent: run Devin (SWE-2 by default) in your terminal for local work, with a /handoff command that sends a task to Devin Cloud when it outgrows your machine.

TL;DR

omarchy pkg add devin-cli

That installs Devin CLI v3000.14.30821-1 (82.5 MB download, 257.7 MB installed; LicenseRef-Cognition, proprietary). Sign in with your Devin account in the browser (devin auth login), then start a session in a project folder with devin. The CLI is included in every Devin plan, including the free tier; it costs nothing extra on top of the plan.

Getting started (5 minutes)

1. Sign in.

Run devin auth login. It opens a browser sign-in through app.devin.ai (a PKCE flow) and stores a persistent token that does not expire on a schedule. Check the result with devin auth status, and sign out with devin auth logout. On a remote machine over SSH, where no browser opens, use devin auth login --force-manual-token-flow and paste the token by hand. Do not skip login: the model list is empty until you do, so nothing runs before you sign in.

2. Start a session.

Change into a project and run devin. Start with a read-only question, for example “Explain the structure of this repo,” so you see how it works before it edits anything. Pick a model with /model inside the session, or pass --model at launch (short names like opus, sonnet, swe, codex, and gemini). SWE-2, Cognition’s own model, is the default, and Cognition recommends Fusion, which pairs a frontier lead model with a cheaper sidekick.

3. Three things worth doing in the first session:

  • Set a permission mode — the default is normal (also called auto). Use --permission-mode accept-edits to let it edit without asking each time, smart for a middle ground, and dangerous (aliases yolo, bypass) only when you know what you are doing. autonomous requires --sandbox.
  • Hand work to the cloud — when a task is long or needs a clean machine, type /handoff in the session to send it to Devin Cloud, where it runs in its own VM and ends in a pull request. The same account covers the CLI, Devin Desktop, and Devin Cloud, and they share one daily and weekly usage allowance.
  • Let it read your existing setup — Devin CLI reads rules, skills, and MCP servers from Cursor, Windsurf, Claude Code, and Copilot in place, with no migration needed. If you do want to migrate another tool’s config into Devin’s own formats, devin migrate handles it. Your own config lives in ~/.config/devin, and your login token in ~/.local/share/devin/credentials.toml. Treat that file as sensitive: anyone with it can sign in as you, so never share it or commit it.

Common issues & fixes

You launch devin and the model list is empty, or no model will run

You are not signed in yet. The model list stays empty until you authenticate, so a fresh install with no login has no models at all, which looks like a broken install but is just missing auth.

Fix: Run devin auth login first, then check with devin auth status and devin models list. (1devtool comparison)

Over SSH, devin auth login opens a browser you cannot reach

On a remote machine there is no browser to open, so the default login flow cannot complete.

Fix: Use the manual token flow instead: devin auth login --force-manual-token-flow. It prints a sign-in URL you open on another device and a token you paste back into the terminal. The same flag is the documented escape hatch for any remote or headless session. (Devin docs, Commands & Flags)

You sign in, but every request fails with a 401 telling you to sign in again

The stored token was refused, which means it is dead rather than expired (Devin tokens do not expire on a schedule).

Fix: Run devin auth logout to clear the stored credentials, then devin auth login again. If you copied credentials.toml between machines, copy it again from a machine where login still works, or just log in fresh. (Devin docs, Devin Auth, magpie opencode-devin-auth notes)

On a company or Enterprise deployment, login succeeds but the CLI exits or cannot authenticate

Enterprise deployments can break the stock login flow: the OAuth token endpoint returns only a short-lived intermediate token, so the durable-key handoff never fires.

Fix: Use the manual token flow (devin auth login --force-manual-token-flow) with the durable key kept in ~/.local/share/devin/credentials.toml. Also check with your admin that your role has the Use Devin CLI permission; without it, access is blocked at the account level. (sbx devin-enterprise-kit, Devin docs, Devin Auth)

Your session stops mid-week with a quota message

Devin bills on daily and weekly usage allowances, not unlimited use. The free tier has a light quota with limited model choice, Pro ($20/mo) has larger daily and weekly quotas, and Max ($200/mo) has significantly higher quotas with no daily cap. Extra usage beyond a plan is covered by prepaid credits at API pricing.

Fix: Check your plan and remaining quota at app.devin.ai/settings/plans before starting a long task. (Troiana Devin guide, Fast.io Devin Pro guide)

Devin CLI is a free way to try an autonomous coding agent (Devin Free, $0)

Devin CLI is a free way to try an autonomous coding agent (Devin Free, $0). What you give up: the free tier has a light quota with limited model choice, so it is a trial, not a daily driver. What you keep: the full CLI, the same SWE-2 model family, Devin Desktop, and the cloud handoff, all on the same account. The honest comparison is Pro at $20/mo, the same price as Claude Pro, with the cloud agent included.

How to switch from Claude Code (~15 minutes per project)

  1. Export from Claude Code: you do not need to export anything. Devin CLI reads Claude Code rules, skills, and MCP servers in place, so your setup carries over without a migration step.
  2. Import into Devin: if you prefer Devin’s own formats, run devin migrate to convert the config. Your project instructions live in whatever rules file you already use; Devin reads them from the same place.
  3. What doesn’t transfer: chat history, Claude-specific slash commands and permission modes (Devin has its own: normal, accept-edits, smart, dangerous, autonomous), and Claude Code’s GitHub Actions integration.
  4. Time estimate: about 15 minutes per project, mostly signing in and picking a model.

Frequently asked questions

Does Devin CLI cost extra on top of a Devin plan?

No. The CLI is included in every plan, including the free tier, and draws on the same daily and weekly usage allowances as Devin Web and Devin Desktop.

What model does it run?

SWE-2, Cognition’s own model, is the default. You can also pick Anthropic, OpenAI, Google, and open models like DeepSeek, Kimi, and GLM with /model or --model, using short names like opus, sonnet, swe, codex, and gemini.

Does it work offline?

No. Every prompt goes to Devin’s cloud, whether the session runs locally in your terminal or as a Devin Cloud session.

Can it use my Claude Code or Cursor setup?

Yes. It reads rules, skills, and MCP servers from Cursor, Windsurf, Claude Code, and Copilot in place, with no migration needed.

Where does Devin CLI store its config?

Config lives in ~/.config/devin, following XDG paths even on macOS. Credentials live in ~/.local/share/devin/credentials.toml (or $XDG_DATA_HOME/devin/credentials.toml if that is set). Session data, including one SQLite database covering every project on the machine, lives under ~/.local/share/devin/cli.

How do I hand a task to the cloud?

Type /handoff inside a session. Devin Cloud picks it up in its own VM and returns a pull request.
