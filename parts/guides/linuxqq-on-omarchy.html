linuxqq on Omarchy

linuxqq is Tencent's official Linux QQ client (the Electron-based "NT" build) for Omarchy — 1-on-1 and group chat, voice/video calls, screen sharing, and file transfer, straight from im.qq.com.

TL;DR

omarchy pkg add linuxqq

Takes ~5 minutes (253.3 MB download / 638.7 MB installed).

Free proprietary app — no paid tier.

Getting started (5 minutes)

1. First launch.

Open QQ from the launcher. Login is via the phone app — QQ desktop clients authenticate through your mobile QQ (QR or account + mobile verification flow), so have your phone ready. The "NT" build is the full Electron client: chat, calls, screen sharing, file transfer, screenshots.

2. The three things everyone needs to know:

  • On Wayland, expect the Wayland tax — and it's documented, not your fault. The linuxqq-wayland-fix project (AUR package too, MIT) exists because stock QQ on Wayland has broken clipboard, crashing screenshots, and broken screen sharing. Read "Common issues" before you judge the app. The fix tool works via LD_PRELOAD injection without touching the official package.
  • Voice/video calls are real here. Unlike some repackaged messengers, the official NT Linux build is a full client — calls included. If you're choosing between this and running Windows QQ in a VM, the VM is ArchWiki's "smallest chance of error" fallback, but it costs the VM's resources.
  • TIM has no Linux version. TIM is QQ's work-oriented variant — if your workplace uses TIM, the ArchWiki's answer is a VM. Don't waste an hour looking for a Linux TIM client.

3. Where its config lives.

Electron app data under ~/.config/QQ or similar — verify the actual path during the on-machine pass. (Marked unverified.)

4. Omarchy-specific note.

Community AUR variants (linuxqq-nt-bwrap, tencent-qq) repackage the same official binary with Bubblewrap sandboxing and Wayland fixes — AUR-only, not in the Omarchy store. The store's linuxqq is the plain official build.

Common issues & fixes

All items below are from the linuxqq-wayland-fix project, the ArchWiki Tencent QQ page, or real user notes — none are invented. Unverified items are marked as such.

Copy/paste between QQ and other apps is broken on Wayland.

The linuxqq-wayland-fix README documents this exactly: "Wayland QQ still uses X11's clipboard, so content copied in QQ can't be pasted outside, and content copied outside can't be pasted into QQ."

Fix: Install the AUR linuxqq-wayland-fix companion (or its approach) — it fixes clipboard via injection without modifying the official package. (linuxqq-wayland-fix)

Pressing the screenshot hotkey instantly crashes QQ on Wayland.

Also documented in the same project's known issues — "clicking the screenshot key on Wayland QQ crashes immediately." Consider this a known defect of the stock build, not your setup.

Fix: Same remedy: the linuxqq-wayland-fix companion. (linuxqq-wayland-fix)

Screen sharing says "cannot use under Wayland" or loops opening the launcher.

Documented failure mode in linuxqq-wayland-fix — Wayland screen share prompts that it can't be used, or loops. Their fix routes through PipeWire/Portal.

Fix: If screen sharing is core to your workflow (work meetings), test this first before committing to the native client. (linuxqq-wayland-fix)

Chinese input (fcitx5) doesn't work, or candidate popups crash QQ on Wayland.

For Electron QQ on Wayland: it needs --enable-wayland-ime to talk to fcitx5 via text-input (the package desktop entry only passes --no-sandbox).

Fix: Two sourced fixes: add --enable-wayland-ime (see the xifan2333/arch-post-install commit), or — a real user who hit candidate-popup crashes after switching to Wayland — env vars including QT_QPA_PLATFORM=xcb (falls back to XWayland) (duanluan/linux-notes).

No tray icon visible on Wayland.

Electron registers a Linux tray icon as a StatusNotifierItem only if a watcher owns org.kde.StatusNotifierWatcher when the Tray is created; otherwise it falls back to an XEmbed icon that no Wayland bar shows — and never retries.

Fix: Unverified for QQ specifically, but the mechanism is documented for Electron apps generally: if your tray icon is missing, check whether the StatusNotifier watcher is up before QQ launches. (robertg761/ha-desktop-widget notes)

QQ crashes when starting a screen share while Easy Effects is running.

From the linuxqq-wayland-fix known issues.

Fix: Add TRAE to Easy Effects' input/output exclude lists, then retry the share. (linuxqq-wayland-fix)

Pairs well with

  • linuxqq-wayland-fix (AUR, MIT) — treat it as a required companion on Wayland, not an optional tweak
  • fcitx5 configured once for the whole desktop
  • PipeWire/Portal stack (needed for the screen-share fix path)

If you hate this, try

  • Windows QQ in a VM — ArchWiki's recommended fallback, "the smallest chance of error," costs VM resources
  • linuxqq-nt-bwrap / tencent-qq AUR variants (same official binary + Bubblewrap sandbox + Wayland fixes)
  • and accept there's no web QQ — the old web.qq.com was retired years ago, so don't go looking

Frequently asked questions

Does linuxqq work on Omarchy?

Yes — it's Tencent's official Electron-based Linux QQ client, packaged for the Omarchy store. Install with omarchy pkg add linuxqq. Budget time for the documented Wayland fixes.

Is linuxqq free?

Yes. Proprietary freeware under Tencent's QQ license (LicenseRef-QQ). No paid tier.

Why is copy/paste broken between QQ and other apps?

The stock build uses X11's clipboard even on Wayland. This is a documented defect, not your config — install the AUR linuxqq-wayland-fix companion (MIT, LD_PRELOAD injection, doesn't modify the official package).

Why does the screenshot hotkey crash QQ?

Another documented Wayland defect of the stock build — same fix companion. Until fixed upstream, treat screenshots-on-Wayland as broken-by-default.

Does QQ support voice/video calls on Linux?

Yes — the NT Electron build is a full client: 1-on-1/group chat, voice/video calls, screen sharing, file transfer. (Verify on-machine during the checklist pass.)

Is there a web version of QQ?

No — the old web.qq.com was retired years ago. Desktop client or VM are the options.
