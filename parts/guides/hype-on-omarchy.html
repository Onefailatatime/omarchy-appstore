Hype on Omarchy

Hype is a native Omarchy desktop app for making presentations from plain Markdown files — a visual slide editor, Overview grid, one-command PDF/PowerPoint export, and a headless CLI your coding agent can drive.

TL;DR

omarchy pkg add hype

It takes ~2 minutes (v0.6.0-1, ~327 KB). Open Hype from the app launcher or run hype in a terminal.

Free forever (MIT). It's built by the Omarchy org (omacom) in C++/Qt, so it feels like a native citizen — your Omarchy themes double as presentation themes.

Getting started (5 minutes)

1. Install and launch.

omarchy pkg add hype, then Super + Space, type "hype", or run hype. Ctrl+N starts a new deck; the app reopens your last presentation on launch. (Confirm the first-launch flow on-machine — this is from the README, not a live test.)

2. First deck.

A presentation is just a Markdown file plus a media folder. The app gives you three views: Visual (click a slide in the sidebar, edit its Markdown under a live preview), Overview (Ctrl+M — a grid of all slides for reordering, duplicating, deleting), and Markdown mode (Ctrl+.` — edit the whole deck's raw source). Autosave kicks in after a 1 s typing pause, so Ctrl+S is almost ceremonial. Slides are separated by --- with blank lines on either side; title, theme, and font live in the file's front matter.

3. The three things everyone needs to know:

  • Themes are your Omarchy themes. Styling comes from installed Omarchy themes (e.g. tokyo-night), saved in the file's front matter — so your deck wears the same palette as your desktop, and the file stays portable (the other computer just needs the same font installed). This is Hype's party trick; no other Markdown-deck tool styles from your window manager theme.
  • Media has its own dialect. One image or video per slide, referenced by filename only — Hype finds the directory. Pasted images auto-convert to lossless PNG/WebP sized for 4K with background compression and a progress bar. Layout comes from image alt text: ![fit](photo.jpg) vs ![span](photo.jpg), ![fit background=blur](diagram.png), ![position=bottom-right size=10%](logo.svg) for corner logos (any of nine positions, 1–100% size, not for videos). svg fenced code blocks render as inline vector drawings that follow theme colors (var(--accent)) and stay vector in PDF. Note the quirk: Hype reads *asterisks* as italic but _underscores_ as underline, not italic.
  • Export is one keystroke. Ctrl+E exports PDF (vector text, images as high-quality JPEG sized to visible area at 4K), Ctrl+Shift+E exports PowerPoint (.pptx — slides become 4K JPEGs, pixel-perfect but not editable; videos embed, GIF/WebP auto-convert to embedded MP4). And the CLI can do it headless: hype export talk/presentation.md talk.pdf.

4. Presenting.

Ctrl+Space or F5 presents from the selected slide; Shift+F5 starts from the beginning. With two displays, slides go to the external display and a Presenter View opens on your laptop — current/next slide, counter, and speaker notes pulled from <!-- comments -->.

5. The agent angle.

Hype ships hype help format — the full slide format spec, machine-readable — plus hype skill install, which installs a Hype skill into ~/.agents/skills/hype/ (Codex) and ~/.claude/skills/ (Claude Code). Every CLI command takes --json. That means your coding agent can build you a deck: hype new talk/presentation.md --title "My talk" --theme tokyo-night, then hype render talk/presentation.md --slide 3 -o slide.png to preview.

6. Where its config lives.

The deck itself is the config: presentation.md plus images/ and videos/ beside it, theme/font in front matter. Backups: every saved version lands in .hype-backups/ next to the deck (restore by copying a .bak over the .md). Crash-recovery snapshots: ~/.local/state/hype/recovery/, with a "Version history" menu in the app. No ~/.config/hype path is documented — the README never mentions one (confirm on-machine).

Common issues & fixes

Sourced from the real GitHub issues on omacom/hype — all four were closed on Oct 14, 2026, and there are zero open issues as of 2026-10-18. This is a young (~1 month) but actively maintained project; fixes below landed in the 0.6.x line.

omarchy pkg add hype fails with "target not found"

The package hit the edge channel first and wasn't on stable on day one (issue #1, opened Sep 20, 2026 — closed same day when the reporter realized the mistake). This is the recurring new-package pattern on the store: edge first, stable on the release train.

Fix: If you see it, your channel just hasn't caught up — check the app page or wait for the next train.

New decks keep the "Untitled" placeholder title instead of the file name

Fixed in 0.6.x (issue #10): the new-deck template wrote title: Untitled into front matter in two places in src/deck.cpp, shadowing the filename fallback, while the CLI's hype new already used the filename. The latest release notes say new presentations take their title from the saved filename unless you set one explicitly.

Fix: If you still see it, update.

SVGs that declare a small size render blurry, and show up as low-resolution bitmaps in PDF

Fixed in 0.6.x (issue #18): the image loader treated an SVG's declared size as its "original size" and never enlarged it, so a 400×240 chart was rasterized at 400×240 then stretched (no selectable text in PDF). Now SVG files stay sharp at any size and remain vector in PDF, and inline svg code blocks stay vector too.

Fix: Update if your SVG exports look soft.

How do I put a logo in the corner of a slide?

Added in 0.6.x (issue #21): ![position=bottom-right size=10%](logo.svg) — any of nine positions (top-left through bottom-right), size 1–100%, default 10%. Works for still and animated images, not videos. Per-slide placement; a global "logo on every slide from front matter" is a separate, still-unbuilt feature.

Hype is a free alternative to Deckset (~$30, Mac-only)

Hype is a free alternative to Deckset (~$30, Mac-only). What you give up, honestly: the Mac-native ecosystem, and a mature visual editor that Deckset users know by heart. What you keep: write Markdown, get beautiful slides — plus things Deckset doesn't have: a headless CLI your AI agent can drive, presenter view, and themes that follow your desktop. Since Deckset is Mac-only anyway, the honest framing is less "switch" and more "the Omarchy-native answer to the same idea." No migration guide applies — but if you're porting a Marp deck, the --- separators carry over; you'll need to adapt Marp's YAML directives and theme CSS to Hype's front matter + alt-text dialect.

Frequently asked questions

Does Hype work on Omarchy?

Yes — it was built for Omarchy by the Omarchy org (omacom). Native Qt6 app, C++/Qt, and your installed Omarchy themes are its presentation themes.

Is Hype free?

Completely — MIT license, no account, no paid tier.

What format does Hype save in?

Plain Markdown (slides separated by ---) plus images/ and videos/ folders beside the file. Theme and font live in the front matter. Backups in .hype-backups/; crash snapshots in ~/.local/state/hype/recovery/.

Can I export to PowerPoint or PDF?

Yes, both built in: Ctrl+E for PDF (vector text), Ctrl+Shift+E for PowerPoint. PPTX slides are 4K JPEGs — pixel-perfect but not editable; videos embed. Per the README, video autoplay/loop behavior inside Microsoft PowerPoint is unverified.

Can I automate or script decks?

Yes — the CLI needs no display: hype new, check, slides, render, export, themes, all with --json, and hype skill install teaches Claude Code / Codex the format.

Hype vs Marp — which should I pick?

Hype if you want a visual slide editor and Omarchy-native theming. Marp if you want the biggest ecosystem and you're happy editing Markdown in VS Code. The --- separators are the same, so switching is mostly adapting directives and themes.
