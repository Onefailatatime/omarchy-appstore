wayshare on Omarchy

wayshare is a free, open-source (Apache-2.0) screen-sharing server for Hyprland — it lets you open your Omarchy desktop from a Mac's built-in Screen Sharing app or from any RDP client (Windows App, Remote Desktop Connection, FreeRDP), with no extra software on the viewer side.

TL;DR

omarchy pkg add wayshare
wayshare setup

Run setup once, inside your Hyprland session. It asks for a password, which monitor to share, and which network to listen on — then it starts the service and shows you the address and username to connect with. That's the whole install; there is no window to open on the Omarchy side, wayshare runs as a background service.

Edge-channel note (unverified): the upstream README says the package is currently only on Omarchy's edge channel and that pacman -Si wayshare on stable reports it as not found. The store lists a 0.4.0-2 build from Nov 13, 2026 — confirm on a real machine whether stable installs it directly or edge is still required.

Getting started (5 minutes)

1. Install and run setup.

Run the two commands above from a terminal inside your Hyprland session (not over SSH — setup needs a live Hyprland session to pick a monitor). Setup saves your choices, starts wayshare, and displays the address and username. It also offers to add ufw firewall rules for TCP 5900 (Apple Screen Sharing) and TCP 3389 (RDP).

2. Connect from a Mac.

Open the Screen Sharing app on your Mac and connect to the address setup printed. Sign in with the username from setup and your wayshare password. Your Hyprland desktop appears, and your Omarchy keyboard shortcuts still work — the Mac's Command key maps to Super by default, which is where Omarchy's shortcuts live. For the best picture and sound, switch the Mac to High Performance mode (see below).

3. Or connect over RDP.

In any RDP client, use your Hyprland machine's address and port 3389, the same username, and an empty domain. Before you send your password, check the certificate's SHA-256 fingerprint against the startup log (journalctl --user -u wayshare -b) — if it differs, stop. RDP has no clipboard or sound support, and login is TLS-only (no NLA or CredSSP).

4. The 3 things you need to know:

  • Two protocols, one password. Apple Screen Sharing (TCP 5900) and RDP (TCP 3389) are both on by default and share the same username and password from setup. The network you pick in setup applies to both.
  • Your monitor follows the viewer. By default wayshare resizes the shared monitor to match the viewer's window and restores it on disconnect. One session owns size changes at a time, and live resize/rotation is only verified on Windows App for iPhone.
  • It runs as a service, not an app. There is no wayshare window. Control it with wayshare start, wayshare stop, wayshare restart, and diagnose it with wayshare doctor. Config lives in ~/.config/wayshare/config.toml — edit it, then run wayshare restart.

5. Config location.

~/.config/wayshare/config.toml. Every key is optional; a full example ships in /usr/share/doc/wayshare/. The useful basics:

output = "DP-1"          # the monitor to share; `hyprctl monitors` lists them
name = "studio"          # how the machine appears on the Mac; default: hostname
listen = "0.0.0.0:5900"  # all networks; use one address to listen only there
resize = true            # match the viewer's size, restore the monitor afterwards

Practical notes: Change the password any time with wayshare set-password + wayshare restart. Pick a different login name with wayshare set-password --user NAME (then point srp_file at the matching file in the config — see the project's configuration doc). On Omarchy, omarchy-update upgrades wayshare with the rest of the system; run wayshare restart afterwards. To remove it: wayshare uninstall, then omarchy pkg drop wayshare (your config in ~/.config/wayshare is kept).

Common issues & fixes

All of these come from the project's own troubleshooting doc — they are the maintainer's documented failure modes, not guesses. Each one is still marked for on-machine confirmation in the checklist above.

The service does not start at login

wayshare doesn't come up after you log in. The service starts with graphical-session.target — Omarchy and other setups that launch Hyprland through UWSM reach that target, but a plain Hyprland launch does not.

Fix: If you launch Hyprland directly (not through UWSM), add this to hyprland.conf:

exec-once = systemctl --user start wayshare

If it still fails, read the log for a config error or a missing monitor (journalctl --user -u wayshare -b), and run wayshare setup inside your Hyprland session to pick an enabled monitor.

“The password is rejected”

The viewer won't accept your login. Usually the wrong username, the wrong password, or (on RDP) a domain sneaking in.

Fix: Use the exact username from setup and your wayshare password. To reset it:

wayshare set-password
wayshare restart

On RDP, the username is case-sensitive and the domain must be empty — remove any saved domain, computer-name prefix, or Microsoft account. If you set a custom username with srp_file, use the matching --srp-file and --user options (see the project's configuration doc, “Login”).

Mac Screen Sharing cannot connect

The Mac's Screen Sharing app fails to connect or hangs. Screen Sharing allows only one window per address, and a stale window — including one hidden behind other windows — blocks a new connection.

Fix: Close any open Screen Sharing window for this machine, including windows behind other windows, and dismiss leftover alerts. Then try the Mac quickstart again. If it still fails, check the Apple port and firewall with wayshare doctor.

The machine does not appear in Finder

Your Omarchy box never shows up in the Mac Finder's sidebar, even though connecting by address works.

Fix: Finder discovery needs mDNS: allow UDP 5353 on your LAN and check that [mdns] enabled = true in your config (it is the default). You can also skip discovery entirely and connect by address through Connection > New in Screen Sharing. Note that RDP clients always use an address — wayshare does not advertise RDP through mDNS.

High Performance is unavailable or falls back to Standard

You select High Performance on the Mac but the connection stays in Standard mode, or HP starts and then drops back. Only one High Performance viewer can connect at a time; later viewers get Standard mode (except a reconnect from the same address, which takes over).

Fix: Run wayshare doctor to check the encoder and install any missing libraries it names (see the project's High Performance doc). To see what's actually happening, follow the log while reconnecting:

journalctl --user -u wayshare -f

If the Mac never requests HP, the UDP feedback timer never starts — close the connection and select High Performance again. If HP falls back, look for no valid video RTCP before HP media stopped; falling back to Standard mode: video gives up after 15 seconds without initial authenticated RTCP feedback (or 10 seconds without further feedback). A common cause on a tailnet is the UDP media path: the default video and sound ports are 5960 and 5962, and wayshare doctor checks the ufw rule for them. One specific tell: if sound starts about 5 seconds after video, look for no initial audio RTCP in the log and a [UFW BLOCK] line with PROTO=UDP and DPT=5962 in the kernel log — rerun wayshare setup to add the UDP rule.

RDP connection is refused or times out

The RDP client can't reach the server at all. RDP is on by default on port 3389 at the Apple listen address — unless it was turned off or the listener never came up.

Fix: Check the startup log for RDP listener ready (or RDP disabled):

journalctl --user -u wayshare -b | grep -i rdp

If you turned RDP off, remove --no-rdp or set [rdp] enabled = true. If RDP bound to loopback, set [rdp] listen (or the top-level listen) to your LAN or VPN address. A RDP disabled line with a repair message tells you the exact fix: a missing SRP record needs wayshare set-password; a TLS identity error needs a valid rdp.identity_file with directory permissions that let wayshare read or create it — then wayshare restart. Once the listener is ready, allow TCP 3389 from your LAN or VPN in your firewall (setup offers the ufw rule; wayshare doctor checks it).

The RDP client shows a certificate warning

Your RDP client warns about the server certificate. wayshare creates a self-signed certificate on first use (~/.config/wayshare/rdp-identity.pem), and its names are localhost, 127.0.0.1, and ::1 — so clients warn when you connect by a LAN address. That warning is expected, but you must verify it before trusting it.

Fix: Check the certificate's SHA-256 fingerprint against the startup log before you send your password — stop if it differs. A SHA-1 thumbprint cannot match a SHA-256 fingerprint; they are different hashes. You can also get the fingerprint straight from the certificate file over a trusted connection:

openssl x509 -in ~/.config/wayshare/rdp-identity.pem -noout -fingerprint -sha256

Accepting the warning without checking identity can send your password to another server. For a client that shows only SHA-1, the same command with -fingerprint -sha1 gives the matching value.

RDP screen stays black or graphics fail

The RDP session connects but the screen is black or graphics are broken. This is a codec negotiation issue, not a connection issue.

Fix: Try the legacy RemoteFX path in ~/.config/wayshare/config.toml:

[rdp]
codec = "remotefx"

Then wayshare restart and reconnect. Avoid egfx-remotefx with the iOS Windows App — it causes protocol errors. For deeper logs, set RUST_LOG=info,wayshare::rdp=debug in the service environment (systemctl --user edit wayshare, add Environment=RUST_LOG=info,wayshare::rdp=debug under [Service]), restart, and watch journalctl --user -u wayshare -f.

Pairs well with / If you hate this, try

Pairs well with

  • tailscale (remote access over your tailnet without router port forwarding — pick tailscale0 as the network in wayshare setup so both protocols bind to your Tailscale address; the store has a Tailscale on Omarchy guide), and ufw (wayshare setup offers the firewall rules for you — TCP 5900/3389, plus UDP 5960/5962 for High Performance).

If you hate this, try

  • gliff — Hyprland remote desktop over SSH with GPU H.264, if you want a single-protocol tool that tunnels over a connection you already have. Or rustdesk — a general remote-desktop app in the TeamViewer mold, if you want a GUI client on both ends instead of using the Mac's built-in Screen Sharing. Or sunshine — if what you actually want is game streaming to Moonlight, not a desktop you can work in.

wayshare is a free alternative to TeamViewer / AnyDesk ($50+/mo) and Apple Remote Desktop ($79.99)

wayshare is a free alternative to TeamViewer / AnyDesk ($50+/mo) and Apple Remote Desktop ($79.99) for sharing a Linux desktop with a Mac. What you give up: a polished GUI client on both ends, a hosted relay that punches through NAT for you, and generic VNC support — wayshare's Apple listener accepts only Apple RFB 3.888/3.889, so generic VNC clients are rejected outright. What you keep: the actual screen sharing, clipboard (on Mac), live resize, and RDP access from Windows and iOS — for $0, with no account and no subscription. The honest trade-off is setup effort: you open firewall ports and pick a network yourself instead of a relay doing it for you, and remote access over the internet means a VPN (Tailscale) rather than port forwarding.

How to switch from TeamViewer / AnyDesk (~15 minutes)

  1. Install wayshare: On Omarchy: omarchy pkg add wayshare, then wayshare setup inside your Hyprland session. Pick a strong password — this is your login now.
  2. Connect your Mac once: Open Screen Sharing, connect to the setup address, sign in. That's the whole client setup — there is nothing to install on the Mac.
  3. Open the firewall: Let setup add the ufw rules (TCP 5900 for Apple, TCP 3389 for RDP), or add them yourself. Verify with wayshare doctor.
  4. For access away from home: Don't port-forward 5900/3389 to the internet. Install Tailscale on both machines and pick tailscale0 as the network in wayshare setup — same connection, no open ports.
  5. What doesn't transfer: Your TeamViewer/AnyDesk contact list and unattended-access setup (there's no account — the address + password is the access), generic VNC clients, and RDP clipboard/sound (Mac High Performance has both; RDP has neither). Uninstall the old client once wayshare is working so you don't have two remote-access doors open.

Frequently asked questions

Does wayshare work on Omarchy?

Yes. It's in the official Omarchy repo as wayshare (version 0.4.0-2, built Nov 13, 2026) and installs with one command: omarchy pkg add wayshare. It needs Hyprland 0.56 or newer and systemd. Note the upstream README's edge-channel caveat (see the TL;DR) — confirm on a real machine whether stable installs it directly.

Is wayshare really free?

Yes. Apache-2.0, no paid tier, no account, no ads. The author accepts sponsorships/donations, but nothing is paywalled. The Omarchy package is 6.5 MB to download and 18.1 MB installed.

What do I connect with?

From a Mac: the built-in Screen Sharing app — nothing to install. From Windows or iOS: Windows App, Remote Desktop Connection (mstsc), or FreeRDP, all tested by the maintainer. Generic VNC clients do not work: the Apple listener only accepts Apple RFB 3.888 and 3.889.

Is it safe to expose wayshare to the internet?

No — don't port-forward it. Both listeners default to all IPv4 interfaces, and Apple Standard-mode screen updates and clipboard travel unencrypted, so anyone watching your network can see them. Keep it on your LAN or VPN: Tailscale is the documented path for remote access. On RDP, always check the certificate's SHA-256 fingerprint before sending your password.

Why is there no wayshare icon in my app launcher?

Because there's nothing to launch — wayshare is a background service. Open a terminal and run wayshare doctor to check it, wayshare setup to change it, wayshare restart after editing the config. If you want a window, that's a different tool (see “If you hate this, try” above).

How do I update wayshare?

On Omarchy, omarchy-update upgrades it with the rest of the system, then run wayshare restart. wayshare upgrade installs the latest upstream release directly (for non-repo installs).

Does RDP support sound and clipboard?

No. RDP has no sound or clipboard support in wayshare. For sound and clipboard, connect from a Mac with Screen Sharing — Standard mode has clipboard, High Performance mode adds HEVC video and sound.
