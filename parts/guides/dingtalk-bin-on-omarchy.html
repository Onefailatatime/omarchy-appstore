dingtalk-bin on Omarchy

dingtalk-bin is Alibaba's official DingTalk Linux client (钉钉) for Omarchy — workplace chat with read-receipts, "DING" urgent alerts, video meetings, and OA workflow tools, in a free (but proprietary) enterprise package.

TL;DR

omarchy pkg add dingtalk-bin

Takes ~10 minutes — it's a big one: 454.9 MB download / 1 GB installed.

Free enterprise platform — core chat/meeting features carry no per-seat fee. Account requires a phone number + SMS verification. Proprietary Alibaba EULA (LicenseRef-DingTalk).

Getting started (5 minutes)

1. First launch and login.

Open DingTalk from the launcher. Account setup requires a phone number with SMS verification (documented in deployment manuals) — have your phone nearby. The Linux build is an official Alibaba client (the AUR dingtalk-bin mirrors Alibaba's own Debian/RedHat releases), so this isn't a Wine hack or a repack.

2. The three things everyone needs to know:

  • It's built for workplace surveillance-adjacent workflows. DingTalk's signature features are read-receipts and "DING" urgent alerts that escalate to SMS/calls. Real users on SourceForge flag two honest drawbacks: half-baked English translations and heavy read/unread staff-status tracking. If your org runs on DingTalk, you know this already; if you're evaluating it, know what you're signing your team up for.
  • The 1 GB install is normal. The official client bundles its meeting stack (the same libconference_new.so that shows up in bug reports). Don't be alarmed by the size — but do make sure you actually need the desktop client before spending a gig: the browser version at dingtalk.com covers light use.
  • If it won't start or shows a blank window after an update, the fix is deleting its config. This is the best-documented Linux issue for DingTalk: after updates, chat windows can render blank — quit the app, rm -rf ~/.config/DingTalk/, relaunch. Details in "Common issues."

3. Where its config lives.

~/.config/DingTalk/ — this is also the folder you nuke to fix the blank-window issue. (Confirm the path on-machine; sourced from the AUR comment fix.)

4. Omarchy-specific note.

No DingTalk-specific Wayland/Hyprland bug reports surfaced in research — the Linux client is primarily tested on UOS/Kylin/Debian-lineage distros, so everything about tray icons, screen sharing, and input methods on Hyprland is currently unverified. Record actual behavior on the box rather than assuming breakage.

Common issues & fixes

Sourced from AUR comments and documented reports — nothing invented. Wayland-specific issues are absent from the record, so they're marked unverified rather than assumed.

Blank/white chat window after updating.

A real AUR comment (sgyhy, 2025-09-24): after updating to 7.8.15.x, chat windows rendered blank. Config corruption across updates is the known pattern — if any UI goes weird after an update, this is the first thing to try.

Fix: Quit DingTalk completely, rm -rf ~/.config/DingTalk/, relaunch. (AUR: dingtalk-bin comments)

Won't launch at all on a modern distro — missing/broken library loads.

A Debian 13 report (CSDN, Nov 2025) traced this to newer glibc's dlopen() refusing libraries with executable-stack flags: dingtalk_dll.so and libconference_new.so fail to load. Observed on Debian 13 — whether Arch/Omarchy hits the same glibc behavior is unverified, but the failure signature (silent refusal to start) and the fix are real.

Fix: patchelf --clear-execstack on those two libraries under the install dir. (CSDN report)

English UI is half-translated or confusing.

Multiple users report half-baked English translations in the Linux client. If your org works in Chinese this is a non-issue; English-first teams should expect rough edges in labels and dialogs. (SourceForge user reviews.)

Fix: No fix — this is the shipped product.

Build/packaging breaks with weird patchelf errors.

An AUR comment traced packaging breakage to environment pollution — a conda environment's patchelf shadowing the system one ("conda也有patchelf"). Edge case, but real.

Fix: If you're building or the install acts strangely, check for conda env interference. (AUR: dingtalk-bin comments)

Tray icon / screen sharing / IME behavior on Hyprland.

The client targets UOS/Kylin/Debian desktops; test and record actual behavior on Omarchy during the verify pass instead of copying assumptions from other Electron/Qt apps.

Fix: Unverified — no sourced reports found either way.

Frequently asked questions

Does dingtalk-bin work on Omarchy?

It's Alibaba's official Linux client, packaged for the Omarchy store — install with omarchy pkg add dingtalk-bin. Wayland/Hyprland-specific behavior (tray, screen share, IME) is currently unverified; the client is primarily tested on Debian-lineage desktops.

Is DingTalk free?

The core platform is free for enterprises (no per-seat fee for chat/meetings); newer 8.x marketing includes premium/AI upsells — no verified pricing, so don't quote numbers. Proprietary Alibaba EULA.

How do I log in?

A phone number with SMS verification is required to create/verify the account.

The chat window is blank after an update — what do I do?

Quit DingTalk, delete ~/.config/DingTalk/, and relaunch. This is the documented fix for config corruption across updates.

DingTalk won't start at all — no window, no error.

Check the library-load failure mode: on newer glibc, dingtalk_dll.so and libconference_new.so can be refused for executable-stack flags. The documented fix is patchelf --clear-execstack on those two libraries (observed on Debian 13; unverified on Arch).

Is there a lighter option than the 1 GB desktop client?

Yes — the browser version at dingtalk.com covers chat and light use with zero install.
