rumb on Omarchy

rumb is a read-only terminal dashboard for Arch and Omarchy that shows what your next update brings — ranked by risk — and what's already failing, tied to the package that owns it. It never asks for root.

TL;DR

omarchy pkg add rumb

Takes about 2 minutes (1.3 MB download, 2.8 MB installed). MIT-licensed open source, free forever — no paid tier, no account. Version 0.1.5 at guide time (October 2026). Project: HANCORE-linux/rumb (created October 18, 2026 — brand new).

Getting started (5 minutes)

1. The mental model.

rumb answers two questions before you ever run omarchy update: what is this update going to touch, and how risky is it? and what's already broken on my machine? The centerpiece is an "eye": a ring with every pending update placed by risk (high/medium/low) and by subsystem sector — kernel, graphics, compositor, toolkit, shell, base, apps. Around it sit tiles: pending updates by risk, problems per day, time since last upgrade, what the pending Omarchy update fixes (read from its release notes), and reclaimable disk space. Everything is read-only — it scans your system and the journal, then tells you. The fixing is still yours to do.

2. Install and run it.

omarchy pkg add rumb   # install
rumb                   # run the dashboard
man rumb               # full manual

Curious without running a scan? rumb --demo (called out by an early user in issue #8) launches the dashboard with sample data — the best way to learn the layout before pointing it at your real system.

3. Learn the three navigations.

Use the arrows to pick a subsystem part and press Enter — a detail window opens over the dashboard showing that part's versions, its pending updates broken down by risk, and its problems. On a pending update, Enter shows its facts beside a dependency graph: what it depends on and what requires it, plus the full risk reason ("why is this high-risk?"). On a crash, Enter shows when it last happened, the signal in plain words, and the functions it crashed in, with the crash site marked. And j on any problem pulls the journal lines for it, matched by program name as well as by name.

4. The three things everyone needs to know:

  • Use it before updating. The dashboard is a pre-flight check, not a post-mortem. Its "before you update" checklist tells you which tool will take the snapshot, whether the update replaces your running kernel or the nvidia driver (i.e., you'll reboot), and whether you have enough free disk space. Read that panel, then run omarchy update.
  • Your terminal decides what you see. rumb draws the eye, icons, and graphs as terminal images. foot and kitty render them properly; ghostty works but the author warns it spends a lot of CPU on the images (not recommended); Alacritty can't display images at all — the eye stays empty and (since v0.1.4) you get an explanatory note in its place. Run it in foot or kitty.
  • It's read-only by design — that's the trust model. It only ever scans and reports; it never asks for root and never changes anything. The trade: when it tells you something is wrong, the fix is a separate step (omarchy update, a reinstall, a config edit). This also makes it safe to run over and over, in demo or on someone else's box.

5. Config location.

No documented config file — behavior is driven by CLI flags and keys (documented in man rumb). Treat "settings persist" claims as unverified.

Common issues & fixes

I don't use Arch — will rumb work on NixOS / Debian / Fedora?

Fix: No. rumb reads Arch package data (pacman) — an open issue (#8, Oct 22, 2026) asks about NixOS support and the requester themselves notes "this program relies on Arch packages such as pacman." The author hasn't committed to other distros. On Omarchy (Arch-based) this is a non-issue; on anything else, rumb simply has no data to show.

The eye and icons are blank — I'm on Alacritty

Fix: Documented limitation, not a bug: Alacritty can't display terminal images, so the eye and icons render empty. Since v0.1.4 the dashboard shows an explanatory note in place of the eye instead of just drawing nothing (release notes). Switch to foot or kitty for the full dashboard; everything text-based (tiles, lists, detail windows) still works anywhere.

rumb eats CPU / memory in my terminal

Fix: Known upstream: ghostty spends a lot of CPU on rumb's per-frame images, and earlier versions grew memory ~15 MiB/s in ghostty. The author explicitly does not recommend ghostty. Recent releases fix the worst of it — pictures are now replaced in place so the terminal keeps one image per picture (ghostty memory stays flat, kitty needs about half the CPU) (release notes). Practical move: run rumb in foot or kitty.

Some problems never show up in the dashboard

Fix: Fixed upstream in v0.1.4: the scan previously stalled or dropped problems when the journal contained lines without a program path (e.g., raw kernel messages). Those lines now also reach the live events (release notes). If you're on an older version, omarchy update pulls the fix.

Pairs well with / If you hate this, try

Pairs well with

  • omarchy update (rumb tells you what the update brings and whether it needs a reboot; the update does the work), btop (live resource graphs to complement rumb's update/problem view), and a timeshift/snapper-style snapshot setup (rumb's pre-update checklist names the snapshot tool — make sure it's actually configured).

If you hate this, try

  • checkupdates (pacman-contrib's own read-only pending-update list — plain text, zero dashboard, no risk ranking), topgrade (runs all your updaters including AUR — but it's interactive and does change your system, the opposite of rumb's read-only philosophy), or octopi/pamac (GUI package managers with update lists, but heavier and no risk ranking or crash analysis).

Verdict: If you want a quick, safe "should I update right now and what's it going to touch?" glance before you update — especially the risk ranking and the crash-to-package tracing — rumb is the only tool that does exactly that, and being read-only makes it safe to run constantly. Pick checkupdates for a minimal list, topgrade when you want to do the updating, octopi/pamac if you want a GUI.

rumb is free — the alternative to updating blind

There is no paid product rumb replaces — paid system-health dashboards are a server/SaaS category, not a desktop pre-update briefing. The honest pitch is narrower: the free alternative to updating blind. What you give up: nothing — a one-line checkupdates can't tell you which updates are risky, which need a reboot, or whether you're about to run out of disk space mid-update. What you keep: your update workflow exactly as it is; rumb just briefs you first.

How to add rumb to your update routine (~5 minutes)

  1. Install it: omarchy pkg add rumb (1.3 MB download; 2.8 MB installed).
  2. Run the briefing: rumb — read the eye (pending updates by risk and subsystem sector), the pending-updates tiles, and the problems panels. Run rumb --demo first if you want to learn the layout on sample data.
  3. Read the "before you update" checklist: it names the snapshot tool, flags whether the update replaces your running kernel or nvidia driver (reboot), and compares free disk space against what the update needs.
  4. Run the update yourself: omarchy update — rumb is read-only and never updates for you.
  5. Re-run after: rumb again to confirm the tiles cleared and no new problems appeared.

Frequently asked questions

Does rumb work on Omarchy?

Yes — it's built for Arch and Omarchy (the Omarchy tile reads pending Omarchy updates from their release notes). Install with omarchy pkg add rumb. It's read-only and never asks for root.

Is rumb free?

Yes. MIT-licensed open source. No paid tier, no account, no telemetry mentioned.

Can rumb install updates or fix problems for me?

No — read-only by design. It shows you what the next update brings and what's already failing, tied to the package that owns it. You fix things with your normal tools (omarchy update, reinstalls, config edits).

What terminal should I use with rumb?

foot or kitty — rumb draws images for the eye and icons. ghostty works but uses a lot of CPU; Alacritty shows an explanatory note instead of the eye because it can't display images.

Does rumb work on NixOS / non-Arch distros?

No — it reads Arch package data via pacman. A NixOS support request is open (Oct 22, 2026) but the author hasn't committed to it.

How do I explore it without scanning my system?

rumb --demo launches the full dashboard with sample data — safe to poke around and learn the keys (Enter for details, j for journal lines, 3 for the updates map).
