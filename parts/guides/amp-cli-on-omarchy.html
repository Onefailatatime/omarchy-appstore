Amp CLI on Omarchy

Amp CLI on Omarchy is Sourcegraph’s frontier coding agent in your terminal: describe a task, and it reads, edits, and tests code across your whole project, with each conversation running as its own thread.

TL;DR

omarchy pkg add amp-cli
amp login
cd ~/your-project
amp

That installs Amp CLI (v0.0.1795478457-1, ~67.8 MB download, ~156.5 MB installed). It is free to install; the Hobby tier costs $0 and lets you bring your own model subscription or API keys with no Amp token fees. Amp-hosted cloud orbs and Amp model credits cost extra. It takes about 2 minutes.

Getting started (5 minutes)

1. Log in.

Run amp login. It opens your browser to sign in to your Amp account at ampcode.com. The CLI can keep several accounts: amp account list shows them, amp account switch <email> picks the active one, and amp logout removes it.

2. Start your first thread.

Change into a project directory and run amp. Every conversation is a thread with its own URL, and Amp can keep working on a thread from the web app or your phone after you close the terminal.

3. Three things worth doing in the first session:

  • Turn the Dial. Before your first message, press Ctrl+S to pick a mode. Amp routes by difficulty, not by model name: low modes are fast and cheap, high modes use frontier models. Picking the right mode matters more than picking a model.
  • Write an AGENTS.md. Amp reads AGENTS.md at the repo root (plus ~/.config/amp/AGENTS.md for your personal rules) and treats it as standing instructions: architecture, build and test commands, review steps. A short one makes every thread better.
  • Bring your own model. On the free Hobby tier you can link a ChatGPT, Claude, or Grok subscription, or add your own API keys, with no Amp token fees. Run amp config model-providers add-chatgpt-subscription to link a ChatGPT plan, or set keys in settings. If you buy Amp credits instead, they are billed at provider list price with no markup.

4. Config location.

User settings live at ~/.config/amp/settings.json (edit with amp config edit), workspace settings at .amp/settings.json in the project (edit with amp config edit --workspace). Workspace values override user values, except for keymap entries. (Unverified on Omarchy; from Amp docs.)

Common issues & fixes

amp: command not found right after installing

The binary is probably not on your PATH in the current shell. (Reported in community cheatsheets for the upstream installer; verify the Omarchy package path on a real machine.)

Fix: Open a new terminal window, or check where the package put the binary with which amp and pacman -Ql amp-cli | grep bin.

amp login works, but scripts and CI fail with an expired session

The session token from amp login expires within about an hour, and the CLI rejects it for non-interactive use (Amp cheatsheet).

Fix: For scripts and CI, create a long-lived access token in Settings on ampcode.com (it starts with sgamp_) and export it as AMP_API_KEY.

Amp asks for approval on every MCP server, or a workspace MCP server never runs

MCP servers are configured under amp.mcpServers in ~/.config/amp/settings.json or the workspace .amp/settings.json. Workspace servers need explicit trust before they run (Amp Code guide).

Fix: Approve workspace servers with amp mcp approve <name>. Add a server with amp mcp add context7 -- npx -y @upstash/context7-mcp.

Amp burns through credits fast, or a simple task uses a frontier model

You probably left the Dial on a high mode. (Amp docs via AgentVera guide.)

Fix: Press Ctrl+S and drop to a lower mode for routine edits; save high modes for hard refactors. On the Hobby tier, linking your own ChatGPT or Claude subscription avoids Amp credit charges entirely.

Amp’s edits ignore your project conventions

Amp only knows what it can read. (Amp Code guide.)

Fix: Add an AGENTS.md at the repo root with your build, test, and style rules. Amp also loads ~/.config/amp/AGENTS.md and ~/.config/AGENTS.md in every project, and falls back to AGENT.md or CLAUDE.md when no AGENTS.md exists.

Pairs well with

  • A good terminal (Ghostty or Alacritty, which Amp’s own docs recommend for clipboard support), git (Amp threads work best with clean commits so you can review diffs), and an AGENTS.md per project.

If you hate this, try

  • Claude Code for a terminal agent tied to a Claude subscription, or Google’s Antigravity CLI (agy, also on the Omarchy store) if your work lives in Google’s ecosystem. Both are covered in their own guides on this site.

Amp CLI is free — the agent costs $0; the cloud machines cost money

Amp’s Hobby tier is free, and it is free in a useful way: all features, no Amp token fees when you bring your own ChatGPT, Claude, or Grok subscription or your own API keys, and free self-hosted orbs and runners. What you pay for is Amp-hosted cloud compute (orbs billed by the minute) and Amp model credits if you buy them. If you run Amp locally with your own subscription, your only cost is the subscription you already pay for. The old $10/day free credit grant was replaced by this Hobby tier on September 13, 2026, so older guides that quote it are out of date.

Frequently asked questions

Is Amp CLI free?

Yes, to install and to use on the Hobby tier ($0). You bring your own model subscription or API keys and pay Amp nothing for tokens. Paid plans buy hosted orb time and credits: Megawatt $20/month, Gigawatt $200/month. Prices are US list prices as of October 2026; check ampcode.com/pricing before you pay.

Who makes Amp now?

Amp Frontier Corporation, an independent company spun out of Sourcegraph in December 2025. It calls itself an agent research lab. The CLI npm package moved from @sourcegraph/amp to @ampcode/cli.

What is an orb?

A cloud machine Amp spins up per thread, with your repo cloned into it. The agent keeps working there after you close your laptop, and you can check on it from the web app or your phone. Orbs are billed by the minute by size; self-hosted orbs on your own Docker or Kubernetes setup are free on the Hobby tier.

Does Amp work offline or run a model locally?

No. Amp is a cloud agent: every task goes to a frontier model through Amp or your own provider keys. For a local-model workflow, look at deepseek-dsh instead.

Where does Amp keep its settings?

User settings live at ~/.config/amp/settings.json (edit with amp config edit), workspace settings at .amp/settings.json in the project (edit with amp config edit --workspace). Workspace values override user values, except for keymap entries. (Unverified on Omarchy; from Amp docs.)
