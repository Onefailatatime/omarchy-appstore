Herdr (Desktop App) on Omarchy

Herdr is the free, open-source (Apache-2.0) desktop app for terminals and coding agents — organize work into spaces and tabs, see which agents need you in one sidebar, and close the window knowing every terminal keeps running on the Herdr core underneath.

TL;DR

omarchy pkg add herdr-app

Launch Herdr from the app launcher, or run herdr-app in a terminal. The Omarchy package installs /usr/bin/herdr-app plus a desktop entry, and pulls herdr-core (>= 0.1.11) in automatically — you never install the core by hand. No account, no signup, no payment. Linux needs a desktop session and a working Vulkan driver; the package already depends on vulkan-driver and vulkan-icd-loader, so a stock Omarchy GPU setup qualifies.

Don't confuse the Herdr packages: herdr-app is this desktop window, herdr-core (hc) is the headless server that actually runs your terminals, herdr is the separate terminal workspace-manager CLI from the same org, and omarchy-herdr is DHH's fork of the workspace manager with Omarchy pane-border support.

Getting started (5 minutes)

1. Install and launch.

Run the command above. First launch lands you in a space: a space holds the work on one machine, usually in one repo. An unnamed space follows its first terminal's folder — name it when you want a label that sticks.

2. The 3 things you need to know:

  • Tabs and panes, with follow-your-folder. Each space has tabs; split a tab into panes to put terminals side by side. New tabs start in the focused terminal's folder. Closing the window does not stop anything — the core keeps running every terminal. Closing a pane or tab does end its terminals. After a reboot, kept panes come back as fresh shells in their last folders, not the old programs — plan long agent runs accordingly.
  • The agents sidebar is the point. It collects agents from all your spaces in one list, including workers started by another agent. Agents that report status show as Working (still busy), Blocked (waiting for you), Done (finished while you were elsewhere), or Idle (not working, or a finished agent you've already seen). Click one to jump to it; a worker without a pane opens in a peek overlay you can promote to a tab.
  • The command palette runs the window. Ctrl+Shift+P shows every command and its key (Cmd+Shift+P on macOS). From a terminal, herdr-app ls, herdr-app status, and herdr-app commands give you the CLI view; herdr-app --skill prints the agent guide for driving the window. Duplicate a shipped layout or mod before editing it — your copies stay yours, the app reloads them on save, and a broken edit keeps the last good version and tells you.

3. Config location.

Personal layouts, mods, and key files are reloaded on save (keys.json holds key bindings). The core's own config is separate: ~/.config/herdr-core/config.toml. App settings (fonts, colors, sounds, privacy) live in the in-app Settings — notably Settings → Updates and Settings → Privacy.

SSH machines: Settings → Machines lets you add a host from ~/.ssh/config so its spaces run their terminals on the remote — remote work keeps running when your local window closes, as long as the remote machine and core stay up. Ctrl-click a live terminal address in terminal text (like t7 locally or vps/t7 on another machine) to peek at it.

Common issues & fixes

The app won't start or shows a blank window

The README is explicit: "Linux needs a desktop session and a working Vulkan driver." The Omarchy package already depends on vulkan-driver and vulkan-icd-loader, but the ICD loader alone is not a driver — make sure your GPU's actual Vulkan driver is installed. On stock Omarchy with mesa this is normally satisfied; on exotic hardware you may need the vendor driver. If it still won't render, note the GPU and driver in the bug report.

The app says it can't use the installed core

Fix: This is an expected path — the README documents that "the app can help install or update a core it cannot use." On Omarchy the package pins herdr-core>=0.1.11 as a dependency, so a plain install should already satisfy it. If you have hc-bin or herdr-core-bin from the AUR installed, note the packaged herdr-core conflicts with both (documented in the PKGBUILD) — remove the conflicting one and reinstall through the store command.

Everything's gone after a reboot

Fix: That's documented behavior, not data loss: "After a reboot or core crash, kept panes get fresh shells in their last folders, not their old programs." The core keeps terminals across window closes, not reboots. For work that must survive, drive it from the core side instead: hc run --bg --name job <command> plus hc wait/hc read, or templates for agent roles — and expect to restart the programs after reboot.

Nerd Font icons render as boxes

This is a real, open bug — but it's Windows-only: issue #356 reports 0.1.12 stopped falling back to the bundled Symbols Nerd Font on Windows. The reporter notes macOS and Linux report the missing glyph correctly, so on Omarchy this specific bug doesn't apply. If you see broken icons on Linux, it's a different bug — check that a Nerd Font is actually selected in Settings.

Themes can't color bold or selected text

Known open limitation: issue #357 — themes can't assign separate colors for bold text (Ghostty's bold-color) or selected text (Ghostty's selection-foreground); bold only changes weight, selection only changes the background. No fix yet; the reporter offered a PR. If bold text is unreadable in your theme, pick colors where weight-only bold still contrasts.

Usage telemetry — is the app phoning home?

The README says "Usage telemetry is on by default in releases. Turn it off in Settings → Privacy." One packaging wrinkle: upstream's self-updating release builds and the packaged Omarchy build differ — the PKGBUILD leaves HERDR_APP_RELEASE unset ("release builds update themselves and send telemetry; pacman owns this one"), so updates come through pacman, not the app. If the Settings → Privacy toggle is present in the packaged build, use it; the verify pass should confirm what it shows.

Pairs well with / If you hate this, try

Pairs well with

  • herdr-core — the server under the app; learn hc and you can drive everything from the shell too.
  • collie-bin — a phone web UI for the AI agents in your terminal, served over Tailscale: your agents, in your pocket.
  • ghostty — the terminal the Herdr window's VT layer is built on (herdr-app vendors Ghostty's VT code).

If you hate this, try

  • zellij — free, open-source TUI workspace manager with layouts and plugins (omarchy pkg add won't find it in this store, but it's a pacman/yay staple). No GUI window, no agents sidebar, no multi-machine core — one static binary with zero daemons.

Herdr is free and open source — no paid tier to undercut

Herdr is free and Apache-2.0, including the desktop app, the core, and the agent skill docs. There is no paid tier to undercut. The honest pitch is the reverse of the usual: this is the open-source tool commercial agent-harness products charge for. What you give up vs. a managed service: someone else's uptime guarantees and a cloud control plane. What you keep: persistent agent terminals on your own machines, multi-machine SSH workspaces, and a protocol (hc schema → OpenRPC/JSON Schema) you can build your own clients against.

Frequently asked questions

Does Herdr work on Omarchy?

Yes. It's packaged for Omarchy (x86_64 + ARM64) as herdr-app with herdr-core as a hard dependency. Linux needs a desktop session and a working Vulkan driver — stock Omarchy qualifies.

Is Herdr free?

Yes — Apache-2.0, by the herdrdev org (herdrdev/herdr-app). No account, no paid tier. Upstream's curl installer is also free.

What's the difference between herdr-app, herdr-core, herdr, and omarchy-herdr?

herdr-app is the desktop window (this guide). herdr-core (hc) is the headless server that runs terminals and agents — installing the app pulls it in automatically. herdr is a separate terminal workspace-manager CLI from the same org. omarchy-herdr is DHH's fork of that workspace manager with Omarchy pane-border support.

Do my terminals survive closing the window?

Yes — that's the whole design: "The window arranges terminals. The core runs them." Close the window, everything keeps running. Rebooting is different: after a reboot, kept panes come back as fresh shells in their last folders, not the old programs.

Does it work on other machines?

Yes. Add an SSH machine in Settings → Machines (or hc machine add on the core side) and its spaces run their terminals there. Remote work keeps running when your local window closes, as long as the remote machine and core stay up.

How do I drive it as an AI agent?

herdr-app --skill prints the agent guide for driving the window; hc --skill (on the core side) prints the one for running and coordinating programs. See the FAQ of the herdr-core guide for the hc commands.

How do I update it?

On Omarchy, through the package manager — the packaged build doesn't self-update the way upstream's curl-installed releases do (documented in the PKGBUILD: "pacman owns this one").
