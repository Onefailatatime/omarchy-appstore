GitHub Copilot CLI on Omarchy

GitHub Copilot CLI on Omarchy brings GitHub’s Copilot coding agent into the terminal: describe what you want in plain language and it reads, edits, and runs code in your project, with deep GitHub integration for issues, pull requests, and actions.

TL;DR

omarchy pkg add github-copilot-cli

That installs GitHub Copilot CLI (188.9 MB download, 260.9 MB installed, depends on gcc-libs and glibc). From your project folder (cd ~/my-project), start it with copilot. On first launch, type /login and sign in with your GitHub account. You need a GitHub account and Copilot access: Copilot Free ($0) works, Pro is $10/month. Then describe what you want done. The Omarchy package version was not shown on the app page — confirm the installed version with copilot --version.

Getting started (5 minutes)

1. Log in with GitHub.

Run copilot in a project folder and confirm you trust that folder, for this session or for future sessions. If you are not signed in, type /login inside the session, or run copilot login from the shell. On a local desktop it opens a browser sign-in; over SSH, in Codespaces, dev containers, or headless Linux it uses the GitHub device flow, showing a one-time code to enter at github.com/login/device. If your organization supplies Copilot, its admin must enable the Copilot CLI policy first. Note that if COPILOT_GITHUB_TOKEN, GH_TOKEN, or GITHUB_TOKEN is set, it silently overrides the stored login, so check those variables if the CLI signs in as the wrong account.

2. Start with a read-only task.

Copilot CLI has three working styles: Interactive (it checks in with you), Plan (it lays out the work for you to approve first), and Autopilot (it keeps going through a task). Start in Plan mode and try: “Take a look at this project and explain its main directories.” It reads the codebase before answering, so you see how it works before it edits anything. Every action is previewed for you to approve before it runs.

3. Three things worth doing in the first session:

  • Pick a model with /model — Copilot offers models from several makers (Claude, GPT, Gemini, and Microsoft’s MAI Code 2), and Copilot Fusion routes each task to a suitable model for you. What you can pin depends on your plan: Pro+ and Max unlock the premium models.
  • Set an AI credit session limit — every model interaction draws AI credits, and Copilot CLI lets you cap what one session can spend, so a long task stays predictable. Pro includes 1,500 monthly AI credits, Pro+ 7,000, and Max 20,000.
  • Use the GitHub tabs — the CLI has built-in tabs to browse issues, pull requests, and gists without leaving the terminal, and /pr manages pull requests. This is the one thing no other agent on this list does as natively: the agent lives where your repos live.

Common issues & fixes

You hit a rate limit, or a model stops answering mid-task

First check the message: Error: You've hit a rate limit means you exceeded the rate limit for that model. If it is a model-specific outage, switch models. GitHub’s own advice during the model incidents of October and November 2026 was the same: choose another model. Seven of the 11 Copilot incidents in that window hit only some models, and six were over within an hour, so check githubstatus.com before reinstalling anything.

Fix: Wait for the reset time the error gives, retry then, or upgrade your plan. Or switch models with /model, or use Copilot Fusion, which picks a healthy model for you. (Enjoy Copilot outage guide)

The CLI signs in as the wrong GitHub account, or login keeps failing

An explicitly exported COPILOT_GITHUB_TOKEN, GH_TOKEN, or GITHUB_TOKEN silently overrides the stored login.

Fix: Check for token environment variables first. Unset the wrong one and run copilot login again. If you are on a remote terminal or headless Linux, use the device-code flow (copilot login --device-code) instead of the browser flow. For GitHub Enterprise Cloud, pass the host: copilot login --host https://example.ghe.com. If SAML SSO applies, authorize the relevant organizations during the browser flow. (Omid Saffari Copilot CLI guide, iTechFaqs Copilot CLI tutorial)

You installed it, but copilot is not found, or the CLI will not start

The standalone installer may have updated your PATH, so restart the terminal first.

Fix: Verify with copilot --version. If it still fails, check the binary is executable (chmod +x on the installed path) and that the required shared libraries are present (ldd on the binary shows what is missing). The Omarchy package depends on gcc-libs and glibc, which Omarchy installs for you, so a missing library usually means a second install from another route is shadowing the package: remove the duplicate and restart the terminal. (GitHub Copilot SDK debugging guide)

Your organization pays for Copilot, but the CLI says you have no access

An organization admin must enable the Copilot CLI policy before members can use it: the CLI does not work on an org plan until that policy is on. This is separate from having Copilot in VS Code.

Fix: Ask the org admin to enable it, or check whether your own account has a personal plan (Copilot Free works with the CLI where available). (Omid Saffari Copilot CLI guide)

An MCP server you added does not show up, or its tools never run

Verify the server works before integrating it: the executable must exist and run on its own, the command path must be correct (use absolute paths), tools must be enabled, and the working directory must be set if the server needs one.

Fix: Check the Copilot home logs directory for the redacted process-<timestamp>-<pid>.log files, which show whether the server process started and what it returned. A server that fails its initialize request never registers its tools, no matter what the config says. (GitHub Copilot SDK debugging guide)

What you give up: Claude’s models and the freedom to pick any provider; Copilot CLI only runs the models GitHub offers, and heavy use burns AI credits that the free allowance may not cover. What you keep: a full agentic loop, plan and autopilot modes, MCP, skills, hooks, and the deepest GitHub integration of any agent here, with a genuine $0 plan to start on. The honest pricing picture, checked against GitHub’s plans page in November 2026: Free is $0, Pro is $10/month (1,500 monthly AI credits), Pro+ is $39/month (7,000 credits), Max is $100/month (20,000 credits), Business is $19 per seat per month, and Enterprise is $39 per seat per month. Check current pricing at github.com before deciding.

How to switch from Claude Code (~15 minutes per project)

  1. Export from Claude Code: your project instructions already live in CLAUDE.md. Copilot CLI reads project instructions from its own config; copy the contents across into the agent instructions file for the project.
  2. Import into Copilot CLI: add MCP servers and skills through the CLI’s config (see /settings inside a session), and connect your GitHub repos: the agent can already see your issues and PRs once you are logged in, with no import step.
  3. What doesn’t transfer: chat history, Claude-specific slash commands and permission modes, and Claude Code’s GitHub Actions integration. Copilot CLI has its own /pr command, hooks, and a GitHub Actions automation path instead.
  4. Time estimate: takes about 15 minutes per project.

Frequently asked questions

Is GitHub Copilot CLI free?

Yes, to start: Copilot Free ($0) includes the CLI, with a limited agent allowance. Pro is $10/month, Pro+ $39/month, and Max $100/month, with larger AI credit allowances. Check GitHub’s plans page for current limits.

What is the difference between Copilot CLI and the old gh copilot extension?

The old gh copilot suggest and gh copilot explain extension is superseded. Copilot CLI is the standalone terminal agent (copilot command, no gh needed), it reads your codebase, edits files, runs commands, and works with issues and PRs. It reached general availability on February 25, 2026.

Do I need the GitHub CLI (gh) installed?

No. Copilot CLI is a standalone tool and does not require gh. Install it with omarchy pkg add github-copilot-cli and run copilot.

Where does Copilot CLI store its config?

Settings are changed with the /settings command inside a session. Logs live under the Copilot home logs directory. Exact paths on Omarchy are unverified and need a live check.

Can I use my own API key or a local model?

Yes, in a limited way: Copilot CLI can run on your own key or a local model without GitHub, which is the fallback when GitHub’s own service is down. The main path is your Copilot plan, though, and model choice is limited to what your plan offers.

Which models can I use?

It depends on your plan. Copilot offers models from several makers (Claude, GPT, Gemini, and Microsoft’s MAI Code 2), and Copilot Fusion routes each task to a suitable model. Use /model to see what your plan lets you pin.
