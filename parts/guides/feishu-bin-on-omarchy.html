Feishu on Omarchy

Feishu (飞书) is ByteDance's all-in-one work suite — messaging, video meetings, and collaborative docs — and this is the desktop client for the China service, not the international Lark app. Install the client that matches your org's service: a Lark account will never log in here.

TL;DR

omarchy pkg add feishu-bin

That's the install. Fair warning: it's a 528 MB download and takes 1.5 GB on disk. It's a proprietary Electron app, not open source. The client is free to download and use; enterprise features are paid — check feishu.cn for current pricing.

Getting started (5 minutes)

1. Know which account you need before you log in.

Feishu is the mainland-China service; Lark is its international sister app from the same company. They are separate services with separately stored data (Dao Insights) — your Lark login will not work here and vice versa. If your employer runs on Feishu, log in with the account they gave you (usually tied to your mobile number, or through your org's SSO). If you're signing up personally, the client walks you through mobile-number registration.

2. Learn these three things first:

  • Messages — the Slack-like chat in the left rail, with threads and pinned docs.
  • Meetings — video calls with screen sharing, the calendar icon next to it.
  • Docs — real-time collaborative documents, the closest thing to Google Docs inside the app.

Everything else — OKRs, approvals, admin panels — can wait until your org actually uses them.

3. Make it behave on Hyprland.

Feishu is an Electron app built with Windows and macOS in mind. On Omarchy it runs, but a few Linux-isms bite: Chinese input needs fcitx5 configured (see issues below), screen sharing in meetings depends on your Wayland portals, and closing the window may or may not minimize to tray. Work through the issues section once and it settles down.

Where config lives: Electron apps on Linux keep their data under ~/.config/. Look for a feishu (or similarly named) directory there after first launch — this needs on-machine confirmation.

Common issues & fixes

The app refuses to launch with a FATAL:setuid_sandbox_host.cc error

Chromium's security model wants its chrome-sandbox helper owned by root with setuid permissions, and AUR-packaged Electron apps sometimes ship it misconfigured (background).

Fix: Launch with the sandbox disabled: feishu --no-sandbox (use the actual binary name from your install). That gets you running immediately, at the cost of disabling Chromium's inner process isolation — acceptable on a work machine running only your employer's app, less great as a daily habit. Unverified for this specific package — confirm whether it launches cleanly first.

In a meeting, screen sharing shows a black screen or the share picker never appears

On Wayland, screen capture doesn't go through X11 anymore — apps must request it through PipeWire and xdg-desktop-portal, which pops the system share picker (background).

Fix: First check the plumbing is alive: systemctl --user status pipewire wireplumber. On Omarchy/Hyprland the portal backend should already be present; if the picker still never appears, the Feishu client may be running through XWayland instead of native Wayland, which breaks portal capture entirely. Unverified for Feishu specifically — whether its screen share works under Hyprland is an open verification item.

You can't type Chinese — pinyin goes in as plain Latin letters

Feishu won't do IME for you; it relies on your system input framework. On Arch-based systems that's fcitx5.

Fix: Install fcitx5-im and fcitx5-chinese-addons, then make sure the environment variables are set before your session starts (GTK_IM_MODULE=fcitx, QT_IM_MODULE=fcitx, XMODIFIERS=@im=fcitx — the standard Arch fcitx5 setup from the Arch Wiki). Electron apps pick up input through the GTK IM module path, so if fcitx5 works in your browser it should work in Feishu too. If the candidate window appears in the wrong place or not at all, try toggling the client between Wayland and XWayland mode. Unverified on this client.

Closing the window kills the app entirely — no tray icon

Electron apps on Linux draw their tray icons through StatusNotifierItem, and whether you see one depends on your bar. Omarchy's waybar needs a tray module enabled to show it at all, and some Electron builds simply never register the icon on Wayland sessions (similar reports).

Fix: Check Feishu's settings for a "close to tray" / "minimize on close" toggle first — if the app doesn't offer it, the window manager can't invent it. Tray behavior unverified.

"Wrong username or password" even though your credentials work on your phone

You're probably logging into the wrong service. Feishu and Lark look nearly identical but are separate backends with separately stored user data (source).

Fix: A Lark account will never authenticate against Feishu's servers. Double-check which one your org uses: if your invite link or admin panel lives on feishu.cn, you need a Feishu account; if it's on larksuite.com, you need Lark — and this client is the wrong download for you.

Feishu's Linux client is free to use

The Linux desktop client is free to download and use — which matters because ByteDance's official support skews Windows/macOS/mobile, and Linux users of China-market work apps are often left with the web client. This package closes that gap. There is no free "Feishu clone" to pitch instead: Feishu is proprietary enterprise software with a free entry tier, and enterprise features are paid (check feishu.cn for current pricing).

Picking Feishu vs Lark, DingTalk, or WeCom (~10 minutes)

  1. Ask your org which service they run on: Feishu (feishu.cn) and Lark (larksuite.com) are separate backends — accounts never cross over. DingTalk and WeCom are separate Alibaba and Tencent products entirely.
  2. Install the matching client: On Omarchy: omarchy pkg add feishu-bin for Feishu; omarchy pkg add dingtalk-bin for DingTalk.
  3. Sign up with the right account: Personal Feishu signup is mobile-number based; most people installing this were invited by an employer, in which case you log in with your org account (often via SSO) and the phone-number question never comes up.
  4. Fix the Linux rough edges: Work through the Common issues section above — Electron sandbox flags, Wayland screen sharing, and fcitx5 input are the three that bite on Hyprland.
  5. What doesn't transfer: Nothing crosses between services — your Feishu chat history, contacts, and docs live on Feishu's backend only, and a Lark login will never authenticate here.

Frequently asked questions

Is Feishu the same as Lark?

No. Same company (ByteDance), nearly identical apps, but Feishu is the mainland-China service and Lark is the international one. They run on separate backends with separately stored data, and accounts do not cross over. Install the client that matches your org's service.

Is Feishu free?

The client and basic use are free; enterprise features are paid. Check feishu.cn for current pricing — treat any pricing claim here as stale and verify there.

Why is the download so big?

528 MB down, 1.5 GB installed — that's a bundled Electron/Chromium runtime plus the app itself. Typical for Electron-packaged enterprise apps; it's not a native lightweight client.

Does Feishu work on Omarchy/Wayland?

It installs with one command and it's an Electron app, so it runs wherever Electron runs. Linux-specific rough edges — sandbox flags, Wayland screen sharing, fcitx5 input, tray behavior — are documented above and pending on-machine verification.
