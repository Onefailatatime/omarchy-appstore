GridCraft on Omarchy

GridCraft is a free, open-source (Apache-2.0 or MIT) Excel clone written from scratch in pure Rust — the Excel ribbon workflow, 513 worksheet functions, PivotTables and charts, with .xlsx as its native format. It is alpha software: fast and fun, but its own authors estimate it is only ~50% ready for real work.

TL;DR

omarchy pkg add gridcraft-bin

Install GridCraft on Omarchy with one command. 45.8 MB download, 98.8 MB installed, version 0.13.0-1. Launch it from the app launcher or gridcraft in a terminal, then try File → New → Sample to open a built-in demo workbook (a quarterly sales dashboard with conditional formatting, sparklines and live charts). No account, no license key, no telemetry. Apache-2.0 or MIT licensed, free forever.

Getting started (5 minutes)

1. Install and launch.

Run the command above, then launch GridCraft from the app launcher or with gridcraft in a terminal. You'll see the familiar Excel layout: ribbon across the top, formula bar, Name Box, and sheet tabs along the bottom.

2. The 3 things you need to know:

  • .xlsx is the native format. Open any Excel workbook directly — styles, formulas (including dynamic arrays), tables, conditional formats, charts, PivotTables and print settings round-trip. It also reads CSV/TSV, opens old Excel 97–2003 .xls files (values, formulas and number formats only), and imports XLSB and ODS worksheet data.
  • File → New → Sample is your playground. The built-in sample builds a whole sales dashboard from GridCraft commands, and is the fastest way to see what works today (513 of Excel's 523 worksheet functions, including LET, LAMBDA, MAP, REDUCE, SCAN, BYROW, BYCOL, MAKEARRAY).
  • AI agents can drive it too. GridCraft ships a CLI, a JSON control channel, and an MCP server, so scripts and AI agents (like Claude Code) can read, calculate, and format spreadsheets programmatically. The desktop app logs to ~/.config/gridcraft/logs (the README points you to attach gridcraft.log to bug reports).

3. Config location.

Settings live at ~/.config/gridcraft/ (logs sit in ~/.config/gridcraft/logs/), and RUST_LOG=debug before the launch command turns up log verbosity for troubleshooting.

Common issues & fixes

All sourced from the project's own docs, gaps doc, release notes, and issue tracker. Nothing below was reproduced on Omarchy — confirm each fix on-machine before relying on it.

Non-Latin script text shows as tofu boxes (□□□)

The data is fine but glyphs don't render — e.g. Thai text in cells shows as empty boxes even when the right font is installed on the system. The data parses correctly (the CLI prints it fine); only glyph lookup fails.

Fix: Reported in issue #1762: GridCraft's script-fallback lists probe a fixed set of font directories, and on systems that install fonts somewhere nonstandard the fallback chain comes up empty. Check where your font lives (fc-list :lang=th for Thai) and symlink it into one of the paths GridCraft probes — the issue's workaround:

sudo ln -s /path/to/NotoSansThai-Regular.ttf \
  /usr/share/fonts/truetype/noto/NotoSansThai-Regular.ttf

Then restart GridCraft. If your workbook's audience needs CJK or Arabic, know going in: the project's own gaps doc lists "text in non-Latin scripts doesn't render or export" as a beta blocker — a real gap, not a config mistake.

Excel asks to repair a .xlsx that GridCraft saved

GridCraft opens and saves .xlsx, but the team is upfront that round-trip fidelity has only been proven on files the team itself created — validation against a corpus of real-world Excel workbooks has not happened yet (gaps.md, beta blocker #1). Complex files with PivotTables, charts, conditional formatting, validation or dynamic arrays are the risk zone.

Fix: Before you send a GridCraft-edited file to someone, open the saved copy in real Excel (or LibreOffice Calc) yourself and look for a repair prompt. Keep a pristine copy of anything important — GridCraft 0.13.0 is alpha, and its own authors estimate ~50% readiness for real work. For brand-new spreadsheets built in GridCraft, this rarely bites; for inherited enterprise workbooks, treat the first round-trip as an experiment.

A formula returns a slightly wrong or stale result

Calculation correctness is a known weak area at alpha: the gaps doc lists 15-significant-digit equality issues, spill ranges not updating after structural edits, and qualified-name breakage after sheet renames (tracked in issues like #57, #133, #139, #140, #134). The 0.13.0 release fixed several function results (PERCENTRANK, YEARFRAC, ISOWEEKNUM, IMSQRT) and added iterative-calculation controls to Options → Formulas (max iterations, max change).

Fix: First, update to the latest Omarchy build (omarchy pkg add gridcraft-bin — the store is tracking 0.13.0 as of 2026-10-29). If a formula looks stale after editing, force a recalc; for circular references, check the new iterative-calculation options. If the numbers still disagree with Excel, trust Excel — this is exactly the class of bug the project's own roadmap flags as next up, and it's worth filing an issue with the workbook attached.

An old .xls file opens, but loses its formatting

GridCraft opens Excel 97–2003 .xls files, but only reads values, formulas, number formats, merges, sizes and names — fonts, fills, borders, charts, pictures, comments, conditional formats and validation are silently dropped, and .xls is never written back (gaps.md).

Fix: Save the file as .xlsx the moment it opens cleanly (File → Save As), then re-apply the lost formatting in GridCraft. If you need the original layout preserved pixel-for-pixel, open it in LibreOffice Calc instead — GridCraft's .xls path is a rescue hatch, not a converter.

GridCraft is a free alternative to Microsoft Excel ($9.99/mo)

GridCraft is a free alternative to Microsoft Excel ($9.99/mo). What you give up: VBA macros, add-ins, real-time co-authoring, and the certainty that any Excel file on Earth opens perfectly. What you keep: the ribbon workflow, 513 of 523 functions, PivotTables, 17 chart types, Solver, conditional formatting, and native .xlsx round-tripping for normal files.

How to switch from Excel (~15 minutes)

  1. Export from Excel: you don't need to — .xlsx is GridCraft's native format. Just point it at your existing files.
  2. Open your files: File → Open, pick the workbook. Everything standard transfers: formulas, dynamic arrays, tables, charts, PivotTables, print settings.
  3. What doesn't transfer: VBA macros (there is no macro engine — this is the big one), COM add-ins, and pixel-perfect fidelity on unusually complex layouts (verify by eye the first time).
  4. Time estimate: open-and-go for most personal spreadsheets. Budget ~15 minutes per complex workbook for the first verify pass.

Frequently asked questions

Does GridCraft work on Omarchy?

Yes — it's published in the Omarchy package store as gridcraft-bin (0.13.0-1, built 2026-10-29). Install with omarchy pkg add gridcraft-bin. It runs natively (no Electron — it's pure Rust on the GPU) and the store lists no special requirements.

Is GridCraft really free?

Yes. The license is Apache-2.0 or MIT at your choice, no account, no license server, no telemetry. It is made by the ArtCraft team (GitHub org storytold).

Can it replace Excel for real work?

For new and ordinary spreadsheets: genuinely yes. For complex, macro-laden, or client-facing workbooks: not yet. The project itself says it's alpha and ~50% ready for real work — keep Excel (or LibreOffice Calc) around for anything where a wrong number costs you money.

Can AI agents use my spreadsheets?

Yes — that's one of GridCraft's unusual strengths. Beyond the GUI it ships a CLI, a JSON control channel, and an MCP server that lets agents read, write, calculate, and format spreadsheet data programmatically.

Does it run in a browser too?

Yes — there's a WebAssembly build you can run locally in a browser, where workbooks are read locally and Save downloads the file to your machine. The Omarchy package is the native desktop app.
