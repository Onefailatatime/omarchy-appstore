yt-dlp on Omarchy

yt-dlp is the free, open-source (Unlicense) command-line downloader for YouTube and 1,000+ other sites — paste a URL, get the video (or just the audio) saved locally, in the quality and format you choose.

TL;DR

omarchy pkg add yt-dlp
yt-dlp --version   # should print 2026.10.26

Then download your first video:

yt-dlp "https://www.youtube.com/watch?v=dQw4w9WgXcQ"

That’s it — the best available video+audio lands in your current directory. No account, no signup, no payment.

Getting started (5 minutes)

1. Install and check the version.

Run the command above. If yt-dlp --version prints something older than 2026.10.26, update through the package manager (see the update note in the FAQ — yt-dlp -U is for standalone binaries, not repo installs).

2. The 3 things you need to know:

  • It’s a terminal tool, not an app. There is no window to open and no icon in your launcher. Everything happens in a terminal: yt-dlp <URL>. If you want a GUI, that’s a different tool (see comparisons).
  • Best quality needs ffmpeg. YouTube serves its best picture and sound as separate streams, and yt-dlp merges them with ffmpeg — which the Omarchy package does not pull in. Install it once: sudo pacman -S ffmpeg. Without it you get a warning and a lower-quality single file instead of the merge.
  • YouTube fights back sometimes. YouTube changes its player code regularly, and its bot checks occasionally block anonymous downloads. When a command that worked yesterday fails today, the answer is almost always: update yt-dlp, then check the Common issues below. Only download videos you have the right to save.

3. Config location.

yt-dlp reads ~/.config/yt-dlp/config — one flag per line, applied to every run. A good starter config:

# ~/.config/yt-dlp/config
--format bv*+ba/b
--merge-output-format mp4
--embed-metadata
--output ~/Videos/%(title)s.%(ext)s

Practical notes: List a video’s available formats with yt-dlp -F URL, then pick one with -f <id>. Grab audio only with yt-dlp -x --audio-format mp3 URL. Download a whole playlist with the playlist URL (add --no-playlist when you only want one video from it). Subtitles: --write-subs --sub-langs en.

Common issues & fixes

“Sign in to confirm you’re not a bot”

Problem: ERROR: [youtube] <id>: Sign in to confirm you're not a bot. Use --cookies-from-browser or --cookies for the authentication. This is YouTube’s bot wall, not a yt-dlp bug: YouTube decided the request looks automated and wants a verified, signed-in session. The canonical report is yt-dlp issue #10128 (June 2024), and the failure is driven by IP reputation, a missing Proof-of-Origin (PO) token, and whether a session cookie is present. Home connections hit it far less than datacenter/VPS IPs. (tunelio.dev, hproxy.com)

Fix: Work through these in order:

# 1. Update — YouTube changes break older builds fast
sudo pacman -Syu yt-dlp

# 2. Make sure a JS runtime is available (needed since 2025.11.12 for
#    full YouTube support; Deno is recommended, Node 22+ also works)
yt-dlp --js-runtimes node "URL"

# 3. Force IPv4 — YouTube scores whole IPv6 /64 ranges as one unit
yt-dlp -4 --rm-cache-dir "URL"

# 4. Cookies, last resort — from a throwaway account, never your main one
yt-dlp --cookies-from-browser firefox "URL"

For the cookie method, the project’s wiki recommends signing in inside a private browser window, exporting the youtube.com cookies to a Netscape-format file, then closing that window so the browser doesn’t rotate the session — then yt-dlp --cookies cookies.txt URL. Treat a cookies file like a password, and know the wiki’s warning: using your account with the tool risks the account being restricted. (yt-dlp FAQ — passing cookies)

“You have requested merging of multiple formats but ffmpeg is not installed”

Problem: You asked for best video + best audio and got a warning instead of one finished file: WARNING: You have requested merging of multiple formats but ffmpeg is not installed. The formats won't be merged. yt-dlp and ffmpeg are separate programs — installing yt-dlp does not install ffmpeg, and the Omarchy package doesn’t declare it as a dependency (only python and nodejs).

Fix: Install ffmpeg and confirm it’s on your PATH:

sudo pacman -S ffmpeg
ffmpeg -version   # should print a version, not "command not found"

Retry the download — the video and audio streams now merge into one file. This also fixes audio extraction (-x --audio-format mp3), which needs ffmpeg for conversion.

“Requested format is not available”

Problem: ERROR: [youtube] <id>: Requested format is not available. Use --list-formats for a list of available formats. A format ID copied from another video (or an old guide) doesn’t exist for this video — available formats vary by video, quality, and codec.

Fix: Don’t guess IDs. List what’s actually there and pick from it:

yt-dlp -F "URL"
yt-dlp -f 137+140 "URL"   # example: pick IDs from the list above

Or stop pinning formats entirely and let yt-dlp choose: yt-dlp -f "bv*+ba/b" "URL" (best video + best audio, falling back to the best single file).

HTTP 403 Forbidden on videos that worked before

Problem: Downloads that worked yesterday now fail with 403. This is the classic “YouTube changed something” failure — a recent instance: in August 2026 the android_vr client in yt-dlp 2026.07.04 started throwing 403s until it was patched in the 2026.08.19 release. Missing PO tokens can also surface as 403s or as missing formats. (videoproc.com)

Fix: Update first — most 403 waves are fixed within days by a new release:

sudo pacman -Syu yt-dlp
yt-dlp --rm-cache-dir "URL"

If it persists on the newest release, check the yt-dlp GitHub issues for the video/site — a YouTube-side change usually has an open issue within hours, and the fix is the next release, not a flag you can add.

Downloads land in the wrong place / filenames are a mess

Problem: Files pile up in whatever directory you happened to run the command from, with YouTube’s default Title [id].ext naming.

Fix: Set a permanent output template once, in ~/.config/yt-dlp/config (see Getting Started) or per-command with -o:

yt-dlp -o "~/Videos/%(title)s.%(ext)s" "URL"

%(title)s, %(uploader)s, %(upload_date)s, and %(playlist)s are the useful placeholders — ~/Videos/%(uploader)s/%(title)s.%(ext)s sorts everything by channel automatically.

Pairs well with / If you hate this, try

Pairs well with

  • ffmpeg (sudo pacman -S ffmpeg — required for merging and audio extraction), mpv (plays anything yt-dlp can fetch, and can stream a URL through yt-dlp directly: mpv "URL"), and aria2c as a faster external downloader (yt-dlp --external-downloader aria2c --downloader-args aria2c:"-x 8" "URL").

If you hate this, try

  • 4K Video Downloader — a GUI app with a click-and-paste workflow and playlist support, if you want buttons instead of a terminal. The free tier caps playlists and quality; the paid tier is ~$15–25/yr. Or yt-dlp’s own front-ends (e.g. ytdlp-gui / Parabolic) if you want a window on top of the same engine. None of them match yt-dlp’s format control or site coverage.

yt-dlp is a free alternative to YouTube Premium downloads ($13.99/mo)

yt-dlp is a free alternative to YouTube Premium downloads ($13.99/mo). What you give up: the official in-app download button, ad-free YouTube, and YouTube Music. What you keep: offline viewing — as real files you own, playable in any player, forever, with no expiry if you cancel anything (there’s nothing to cancel). For someone who only wants to save a few videos for offline watching, that’s the entire download feature of a $168/year subscription at zero cost.

How to switch from YouTube Premium downloads (~10 minutes)

  1. Install yt-dlp: On Omarchy: omarchy pkg add yt-dlp, plus sudo pacman -S ffmpeg for best-quality merges.
  2. Re-download what matters: Premium downloads live inside YouTube’s app and vanish when you cancel. For each video you want to keep, run yt-dlp "URL" — the URL is in the video’s Share menu. Playlists download in one command with the playlist URL.
  3. Set your library folder once: Add --output ~/Videos/%(title)s.%(ext)s to ~/.config/yt-dlp/config so everything lands in one place.
  4. What doesn’t transfer: Your in-app download list itself (there’s no export — re-download from the URLs), ad-free playback, and background play in the YouTube app. If you watch mostly in a browser, an ad-blocker covers the ads; if you watch on your phone, that’s the actual cost of switching.

Frequently asked questions

Does yt-dlp work on Omarchy?

Yes. It’s in the official Omarchy repo as yt-dlp (version 2026.10.26-1, added Nov 12, 2026) and installs with one command: omarchy pkg add yt-dlp. It’s a terminal tool — there’s no app window, you run it from any terminal.

Is yt-dlp really free?

Yes. It’s released under the Unlicense (public domain) with no paid tier, no account, and no ads. The Omarchy package is 2.9 MB to download and 3.1 MB installed.

Is yt-dlp legal?

The tool itself is legal open-source software — a maintained fork of youtube-dl. What matters is what you download: only save videos you have the right to download (your own uploads, Creative Commons / public-domain content, or videos where the creator permits it). Downloading copyrighted material you don’t have rights to can violate YouTube’s terms and copyright law.

Why is there no yt-dlp icon in my app launcher?

Because there’s nothing to launch — yt-dlp is a command-line program. Open a terminal and type yt-dlp <URL>. If you want a window, look at a GUI front-end (see “If you hate this, try” above).

How do I update yt-dlp?

Through the package manager (sudo pacman -Syu yt-dlp), not yt-dlp -U — that flag only works for standalone binaries, not repo installs. YouTube changes break old builds quickly, so update whenever a download starts failing for no apparent reason.

Why does YouTube sometimes say “Sign in to confirm you’re not a bot”?

YouTube’s anti-abuse system flagged the request — usually IP reputation or a missing PO token, not anything you did wrong. Update yt-dlp, make sure a JS runtime is available (--js-runtimes node), and retry. Cookies from a signed-in session are the last resort, and only from a throwaway account.
