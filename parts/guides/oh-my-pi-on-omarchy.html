Oh My Pi on Omarchy

Oh My Pi (omp) is a free, open source terminal coding agent that wires your IDE’s language servers and debuggers straight into the agent, so it can rename, refactor, and debug code the way your editor does.

TL;DR

omarchy pkg add oh-my-pi

That installs omp v19.1.1-1 (~179.6 MB download, ~301.2 MB installed, MIT licence). The app itself is free, but you still pay for the model you use: bring your own API key or a subscription login for one of the 60+ supported providers.

Getting started (5 minutes)

1. Launch it in a project.

Open a terminal inside any code repo and run omp. The TUI opens in that directory, so the agent already knows your project layout.

2. Sign in to a model provider.

On first run, omp needs a model to talk to. Run /login inside the TUI and pick a provider (Anthropic, OpenAI, Google, OpenRouter, and 60+ others are supported). You can log in with a subscription or paste an API key. If you would rather configure it by hand, providers live in ~/.omp/agent/models.yml and preferences in ~/.omp/agent/config.yml, with API keys read from environment variables at runtime.

3. Three things worth doing in the first session:

  • Pick your model with /model. omp supports different models for different roles in one session: a fast model for edits, a stronger one for planning, and a reviewer model as an “advisor” that watches every turn and flags mistakes.
  • Ask for a real refactor, not a text edit. Try renaming a symbol across the codebase. omp routes the rename through the language server (LSP), so imports and re-exports update too, instead of a find-and-replace that misses aliases.
  • Run /review before you commit. It spawns reviewer subagents that sweep your branch or uncommitted changes and rank issues P0 through P3 with a ship-or-don’t verdict.

4. Config location.

Providers and models live in ~/.omp/agent/models.yml, preferences in ~/.omp/agent/config.yml. Sessions and memory are stored under ~/.omp/ as well.

Practical notes: Other commands worth knowing: /collab shares a live session by link or QR code, Alt+A opens the Agent Hub to watch or steer subagents, and omp -p "do X" runs a one-shot prompt without opening the TUI.

Common issues & fixes

omp crashes on launch after installing a plugin built for upstream Pi

This is a real upstream bug (issue #4766): plugins written against Pi’s editor API passed arguments in Pi’s order, while omp’s editor constructor expected a different order, so the first render threw TypeError: undefined is not an object. The maintainers reproduced it and shipped a fix that accepts both constructor orders.

Fix: If you hit it on an old version, remove the plugin (omp uninstall <plugin>) and update omp. Unverified on the Omarchy package: the store ships v19.1.1, well past the fix, so this should already be resolved.

omp crashes immediately on Linux with “Cannot access ‘currentThemeName’ before initialization”

This was an early-2026 bug (issue #10) in the Bun-based build: a circular module import left the theme uninitialized on Linux only. It was fixed upstream in February 2026. The Omarchy package ships a much newer version, so you should not see it.

Fix: If a fresh install crashes on launch, update the package first (omarchy update) before debugging anything else.

The agent loops, ignores your AGENTS.md instructions, or corrupts plan files

This is a reported user experience, not a confirmed bug: some users on newer releases report omp looping in “thinking mode” and ignoring project instructions, while others report the same releases working fine. (Hacker News discussion) Treat this as unverified: no reproduction was run for this guide.

Fix: Keep AGENTS.md short and specific, use the advisor role (a second model watching each turn) to catch drift, and pin a known-good version if a release misbehaves. omp ships releases almost daily and minors carry breaking changes, so a version that worked last week can change behavior.

A minor update breaks your setup or an extension stops working

Expected with this project: releases ship almost daily and minor versions carry breaking SDK changes (for example, v18.11.0 removed ApprovalDetailsOptions, v18.12.0 replaced an env var). (Release history)

Fix: If an update breaks you, check the CHANGELOG for the version you just got, and pin a version until your extensions catch up.

LSP features (rename, go-to-definition) do nothing or report no language server

omp talks to language servers, but it does not install them for you. (LSP config docs) Unverified on Omarchy: not tested with a real project.

Fix: Install the language server for your language (for example, typescript-language-server for TypeScript, rust-analyzer for Rust) and make sure it is on your PATH. omp’s LSP docs list the supported servers per language.

  • Upstream Pi (badlogic/pi-mono) — the minimal agent omp forked from: same TUI idea, far fewer built-ins. Or use Claude Code if you want one vendor’s polished agent instead of a bring-your-own-model toolkit.

Oh My Pi is a free alternative to Claude Code ($20/mo)

Oh My Pi is a free alternative to Claude Code ($20/mo). omp is free and open source (MIT), and it replaces paid coding agents that charge $20/month or more for a subscription. What you give up: a single vendor’s hosted account, usage-based billing in one place, and someone else handling model updates. What you keep: the full agent, LSP and debugger integration, subagents, live collaboration, and your choice of any of 60+ providers. The honest pitch: the software is free forever; you pay the model provider per token instead of paying an agent vendor a subscription. If you already pay for Claude Pro or an OpenRouter balance, omp costs you nothing extra.

Frequently asked questions

Is Oh My Pi free?

Yes. The app is MIT-licensed and free to install and use. You pay separately for model usage: API keys are billed per token by the provider, or you log in with a subscription you already have.

What is the difference between omp and Pi?

omp is a fork of Mario Zechner’s Pi coding agent, rebuilt by Stencil Labs with a Rust core. It adds LSP and debugger (DAP) integration, subagents, live collaboration, an advisor reviewer model, and many more built-in tools, while keeping Pi’s TUI and slash-command style.

Do I need an API key?

You need some way to pay for a model: an API key from a provider, or a subscription login via /login. omp itself has no account and no hosted backend.

Does it work with local models?

Yes, if your local model server speaks an OpenAI-compatible API. Point a provider entry at your local endpoint in ~/.omp/agent/models.yml. Unverified on Omarchy: not tested with a local server for this guide.

Where does omp store its settings?

Providers and models in ~/.omp/agent/models.yml, preferences in ~/.omp/agent/config.yml. Sessions and memory are stored under ~/.omp/ as well.
