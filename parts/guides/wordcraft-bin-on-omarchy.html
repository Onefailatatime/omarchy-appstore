WordCraft on Omarchy

WordCraft is a free, open-source (Apache-2.0 or MIT) Microsoft Word clone written from scratch in pure Rust — the ribbon, styles, tables, track changes, and mail merge you already know, with .docx as its native format. It is alpha software: its authors estimate ~60% readiness for real work.

TL;DR

omarchy pkg add wordcraft-bin

Install WordCraft on Omarchy with one command. 104.2 MB download, 210.1 MB installed, version 0.12.0-1. Launch from the app launcher or wordcraft in a terminal, open any .docx directly — no conversion, no import wizard. No account, no license key, no telemetry. Apache-2.0 or MIT licensed, free forever.

One note: on Hyprland it runs through XWayland by default; start it with WORDCRAFT_WAYLAND=1 wordcraft for native Wayland (see Common issues).

Getting started (5 minutes)

1. Install and launch.

Run the command above, then launch WordCraft from the app launcher or with wordcraft in a terminal. The first screen is the Word workflow you know: a ribbon of tabs (Home, Insert, Layout, References, Review, View), a styles gallery, and a page canvas.

2. The 3 things you need to know:

  • .docx is the native format. It opens and saves Word documents directly — including password-protected ones — and also opens Word 97–2003 .doc files. It reads and writes .odt, .rtf, HTML, Markdown, LaTeX and plain text, and exports PDF with real selectable text, links, and bookmarks.
  • Use Styles, not manual formatting. 505 of Word's 520 ribbon commands are implemented (counted at the 0.12.0 tag), and styles are the fastest way to make a document look right and stay consistent. Track Changes and Comments live on the Review tab.
  • The interface speaks your language. As of recent builds the UI ships in 26 languages and follows your system language automatically — handy on a multi-language machine.

3. Config location.

Settings and logs live at ~/.config/wordcraft/ — the log at ~/.config/wordcraft/logs/wordcraft.log is what you attach to a bug report (it never contains your document text), and auto-recovery copies of unsaved work sit in ~/.config/wordcraft/recovery. Run RUST_LOG=debug wordcraft for verbose logs.

Common issues & fixes

All sourced from the project's own docs, release notes, and changelog. Nothing below was reproduced on Omarchy — confirm each fix on-machine before relying on it.

Text looks blurry with fractional scaling on Hyprland

On a Wayland desktop like Omarchy's Hyprland, WordCraft runs through XWayland by default, because the windowing library it uses only supports dragging files into a window on X11. XWayland means the app is upscaled by the compositor, so at fractional scales (1.25x, 1.5x) text looks softer than native apps (source).

Fix: Launch it natively on Wayland:

WORDCRAFT_WAYLAND=1 wordcraft

Text gets sharp, but you lose drag-and-drop into the window (open files via File → Open instead). Pick whichever trade-off bugs you less; there's no perfect setting yet.

A saved .docx looks wrong when reopened in real Word

WordCraft's .docx round-trip has documented limits. Since v0.5.0, charts, SmartArt and OLE objects are preserved on save but can't be edited; Office 2016 charts with their data and the glossary survive since 0.8.0; drawing canvases survive, but ink inside groups and canvases is lost. And the team has never measured the round trip against a corpus of real documents — only their own files (source).

Fix: Before sending an important file, open the WordCraft-saved copy in real Word or LibreOffice Writer and check it — especially anything with charts, SmartArt, ink annotations, or heavy styling. Since v0.8.0 a failed save tells you why and keeps the document open (previously you could lose work silently), so at least the failure mode is honest now (v0.8.0 changelog).

First keystroke gets dropped after clicking the toolbar

In builds around 0.8.0, the first keystroke after clicking a ribbon/chrome element could be swallowed, and pressing Space or Enter could reset the X11 input context (breaking IME/compose input). Both were fixed upstream in 0.8.0 (changelog).

Fix: Make sure you're on the current Omarchy build (omarchy pkg add wordcraft-bin — the store is at 0.12.0-1 as of 2026-10-29). If input still misbehaves on Hyprland, the native-Wayland launch (WORDCRAFT_WAYLAND=1) uses a different input path and is worth trying; if it persists, it's an upstream bug — file it at storytold/wordcraft with your compositor and build version.

The app offers to update itself at startup

Since 0.12.0, WordCraft shows an update prompt at startup that can install a new version by itself. On Omarchy the package is managed by pacman (omarchy pkg), so a self-update can put the app out of sync with your package manager.

Fix: Dismiss the in-app update prompt and update through Omarchy instead (omarchy pkg add wordcraft-bin pulls the newest packaged build). Two copies of the truth — the package manager's version and the self-installed one — is how you end up with two conflicting WordCrafts.

WordCraft is a free alternative to Microsoft Word ($9.99/mo). What you give up: VBA macros, real-time co-authoring, and guaranteed fidelity on complex documents (charts, SmartArt and OLE survive saves but can't be edited; ink in grouped canvases is lost). What you keep: the ribbon, styles, tables, track changes, mail merge, .docx round-tripping for normal documents, and PDF export with selectable text — for $0, forever, offline.

How to switch from Word (~15 minutes)

  1. Export from Word: nothing to export — .docx is WordCraft's native format. Just open your existing files.
  2. Open your files: File → Open. Normal documents (text, styles, tables, footnotes, track changes) transfer cleanly.
  3. What doesn't transfer: macros/VBA, ink in grouped canvases, editability of charts/SmartArt/OLE objects (they're preserved, not editable), and your Word templates/add-ins.
  4. Time estimate: instant for most personal documents. Budget ~15 minutes per complex file for a verify pass against real Word before you trust it.

Frequently asked questions

Does WordCraft work on Omarchy?

Yes — it's in the Omarchy package store as wordcraft-bin (0.12.0-1, built 2026-10-29). One command: omarchy pkg add wordcraft-bin. It's a native Rust app on the GPU (no Electron), and the store lists no special requirements.

Is WordCraft really free?

Yes. Apache-2.0 or MIT license, no account, no payment, no telemetry, and you can build it yourself from the public repo. It's made by the ArtCraft team (GitHub org storytold), part of their 13-app "Crafting Apps" suite alongside GridCraft (Excel) and DeckCraft (PowerPoint).

Can it replace Word for real work?

For new documents and everyday writing: genuinely yes — its authors estimate ~60% readiness for real work. For documents where fidelity is contractual (client filings, resumes, anything with complex layout or macros): keep Word or LibreOffice Writer in the loop for a final check.

Does it run natively on Wayland?

By default it runs through XWayland (drag-and-drop works, fractional scaling is soft). Launch with WORDCRAFT_WAYLAND=1 wordcraft for native Wayland with sharper text, at the cost of drag-and-drop.

Can AI agents use my documents?

Yes — like its sibling GridCraft, WordCraft ships a CLI and an MCP server, so scripts and AI agents can read, write, and transform documents programmatically.
