linux-t2 on Omarchy

linux-t2 is a patched Linux kernel for Intel Macs with Apple's T2 security chip (2018–2020 MacBook Pro/Air, Mac mini, iMac Pro) — it is the kernel that makes the keyboard, trackpad, Wi-Fi, audio, and fans on those machines work under Linux at all, and on Omarchy it turns a T2 Mac into a native Omarchy machine.

TL;DR

omarchy pkg add linux-t2

It takes ~2 minutes (164.1 MB download, 164.1 MB installed). Then reboot and pick the linux-t2 entry in your bootloader — and do not remove the stock kernel until you have booted linux-t2 successfully at least once. That's the install. There is no app to open and no window to configure — a kernel is the part of the system everything else runs on top of. The real work is the first boot, the checks below, and the three companion packages (Wi-Fi firmware, audio config, fan daemon) that the kernel alone doesn't provide.

Only install this on a T2 Mac. If your machine is not an Intel Mac with a T2 chip (2018–2020), this kernel buys you nothing — boot the stock linux kernel or Omarchy's own linux-omarchy instead. Installing a T2 kernel on a non-T2 machine is harmless but pointless. If you are unsure whether your Mac has a T2 chip, Apple lists the models on its support site (linked in Sources).

Back up first (unverified, common sense): a kernel swap can leave a machine unbootable if the bootloader entry is wrong. Before installing, make sure you have a bootable macOS Recovery or a live USB you can reach by holding Option at boot, and keep the stock kernel installed as a fallback entry.

Getting started (5 minutes)

1. Install, then check what landed.

Run the install command above, then confirm the kernel image and initramfs are in place:

pacman -Qi linux-t2
ls /boot/vmlinuz-linux-t2 /boot/initramfs-linux-t2.img
uname -r   # still shows your OLD kernel — that changes after the reboot

2. Reboot and pick linux-t2 in the bootloader.

On Omarchy (systemd-boot), the boot menu should list a linux-t2 entry next to your existing one. Select it. If no linux-t2 entry appears, do not force it — stop and check the bootloader config (see "No linux-t2 entry in the bootloader" below).

3. Check the kernel actually booted.

Once you're at the desktop, open a terminal:

uname -r
# expect something like: 7.2.15-arch1-1-t2 (exact string unverified — confirm on a real boot)

Then run the three checks that matter: type on the built-in keyboard, move the trackpad, and open a terminal. Keyboard and trackpad on a T2 Mac run through the apple-bce module that this kernel ships — if they work at the login screen, the core of the kernel is doing its job.

The 3 things you need to know:

  • The kernel alone is not the whole machine. linux-t2 gets the keyboard, trackpad, and basic hardware talking. Wi-Fi and Bluetooth still need firmware (apple-bcm-firmware-fetcher), audio still needs its config package (apple-t2-audio-config), and the fans still need their daemon (t2fanrd). All four are in the Omarchy store and were added the same day as this kernel — install them before judging whether "everything works."
  • Keep the stock kernel until linux-t2 has booted cleanly. The old kernel entry is your rescue path. Only remove it once you have booted linux-t2, confirmed keyboard/trackpad/Wi-Fi/audio, and rebooted a second time without surprises.
  • Kernel parameters matter on T2 hardware. The t2linux wiki requires intel_iommu=on iommu=pt pm_async=off on the kernel command line (IOMMU on in passthrough mode, async power management off). Check whether your bootloader entry already carries them — if it doesn't, add them before declaring the install done (see the checklist above).

Config location.

A kernel has no ~/.config file. What you can inspect and change:

# What kernel is running, and with what parameters:
uname -r
cat /proc/cmdline

# Which T2 modules are loaded:
lsmod | grep -E 'apple|brcmfmac'
# expect: apple_bce, apple_ib, brcmfmac among others (exact list unverified)

# Bootloader entries (Omarchy / systemd-boot):
ls /boot/loader/entries/

Practical notes: On Omarchy, omarchy-update upgrades linux-t2 with the rest of the system. After a kernel update, reboot promptly — you keep running the old kernel until you do. To remove it: omarchy pkg drop linux-t2, then reboot into the stock kernel entry and confirm the machine still boots before you consider the removal finished. If you build out-of-tree modules (DKMS, e.g. for VPN or display drivers), install linux-t2-headers too — it's the matching headers package for this kernel, 92.2 MB download / 340.8 MB installed.

Common issues & fixes

All of these come from the t2linux wiki's Arch installation guide and post-installation guide, the archiso-t2 project docs, and Apple's own Startup Security Utility documentation — they are the project's documented failure modes, not guesses. Each one is still marked for on-machine confirmation in the checklist above.

The Mac won't boot the installer / Linux at all — Secure Boot blocks it

A T2 Mac refuses to boot anything that isn't macOS. By default the T2 chip's Startup Security Utility is set to Full Security and disallows booting from external media, so a Linux USB (or an unsigned Linux bootloader) never gets a chance.

Fix: Do this in macOS before you install anything. Restart into macOS Recovery (hold Command+R at boot), then open Utilities → Startup Security Utility from the menu bar. Set Secure Boot to No Security (Full Security only allows Apple-trusted operating systems; Medium Security allows any Apple-trusted OS ever, which still excludes Linux) and set External Boot to Allow booting from external or removable media. This is Apple's own documented procedure — see the Apple support link in Sources. Note this is a one-time firmware setting, not something linux-t2 changes: the kernel cannot lower Secure Boot for you, and it cannot boot at all until you do. (Unverified on Omarchy specifically: the exact Secure Boot level the Omarchy install path needs. The wiki's pre-install steps have you lower it; confirm whether Medium Security suffices or No Security is required.)

No Wi-Fi or Bluetooth after booting linux-t2

The kernel loads the brcmfmac driver for the Broadcom BCM4377 Wi-Fi/Bluetooth chip, but the driver has no firmware to load — Apple's Broadcom firmware blobs are proprietary and are not shipped in the kernel package. Wi-Fi simply doesn't appear.

Fix: Install the fetcher from the store and run it — it extracts the firmware from macOS (which is why the wiki's install guide lists it as a required package alongside the kernel):

omarchy pkg add apple-bcm-firmware-fetcher
# then run the fetcher as its docs describe, and reboot

After the firmware lands in /lib/firmware/brcm/, brcmfmac picks it up on the next boot and Wi-Fi appears. Two gotchas from the project docs: the mainline Bluetooth module hci_bcm4377 conflicts with the T2 Bluetooth setup and must stay blacklisted (modprobe.blacklist=hci_bcm4377 on the kernel command line — the archiso-t2 GRUB config carries it), and if you installed from the t2linux Arch ISO the firmware was already included, so this only bites installs that added the kernel to an existing system. (Unverified: the exact fetcher command name and whether it needs a macOS partition present to extract from — confirm on a real machine.)

No sound — speakers and headphones are silent

The kernel recognises the T2 audio hardware, but without the ALSA/UCM configuration the sound server has no routing for it. The wiki lists apple-t2-audio-config as a required package for exactly this reason, and it depends on sof-firmware (Sound Open Firmware for the T2 audio DSP).

Fix: Install the audio config package from the store and reboot:

omarchy pkg add apple-t2-audio-config

Then check that the output device shows up in your sound settings. If it still doesn't appear after a reboot, check that sof-firmware came along as a dependency and look at the audio devices the kernel sees (aplay -l, pactl list sinks — exact expected output unverified). Do not reinstall the kernel for an audio problem: on T2 Macs, silent audio after a kernel install is almost always the missing config package, not the kernel.

Touch Bar shows the wrong keys — or Touch ID does nothing

On a Touch Bar MacBook Pro, the Touch Bar works in its default mode (the same mode as Windows Boot Camp — function keys), but it doesn't behave like it did in macOS, and Touch ID never works at all.

Fix: Set expectations first, then tune what can be tuned. Touch ID has no Linux support — the wiki's post-install guide is explicit that the internal USB Ethernet interface tied to Touch ID services lacks Linux support, so fingerprint login is simply unavailable; use a password or another auth method. For the Touch Bar itself, the driver (apple-ib) was upstreamed into the mainline kernel in 6.15, so the bar lights up under linux-t2. If you want to change what it shows (function keys vs. media keys), the wiki documents switching the default mode through kernel module options, and the tiny-dfr package gives a customisable Touch Bar daemon with F1–F12 emulation — but tiny-dfr is not in the Omarchy store as of this writing, so on Omarchy that route means building it from source (github.com/kekrby/tiny-dfr). (Unverified: which Touch Bar mode linux-t2 defaults to on Omarchy, and whether tiny-dfr builds cleanly against linux-t2-headers.)

Fans stuck at full speed — or silent while the machine gets hot

The T2 chip controls the fans, and the kernel doesn't drive them by itself. Without the fan daemon the machine either roars or cooks.

Fix: Install and enable the daemon from the store — the wiki's Arch install guide lists this as a required step, not an optional extra:

omarchy pkg add t2fanrd
sudo systemctl enable t2fanrd
sudo systemctl start t2fanrd

Check it's running with systemctl status t2fanrd. If fans still misbehave after enabling it, the wiki notes the daemon is the component that owns fan control — a fan problem with t2fanrd running is a daemon issue to take to the t2linux Matrix/Discord, not a reason to swap kernels.

No linux-t2 entry in the bootloader after install

You installed the package, rebooted, and the boot menu only offers the old kernel. The kernel image is in /boot, but no bootloader entry points at it.

Fix: First confirm the files are actually there (ls /boot/vmlinuz-linux-t2). On Omarchy's systemd-boot setup, entries live in /boot/loader/entries/ — check whether a linux-t2 entry exists and what kernel parameters it carries; the wiki's systemd-boot instructions say to make sure the entry boots linux-t2 and carries intel_iommu=on iommu=pt pm_async=off on its options line. If you are on GRUB instead, the wiki's GRUB path is to add those same parameters to GRUB_CMDLINE_LINUX in /etc/default/grub and regenerate with grub-mkconfig -o /boot/grub/grub.cfg. (Unverified: whether Omarchy's install hook creates the systemd-boot entry automatically — this is the single most important checklist item, because a missing entry is the most likely first-boot failure.)

Pairs well with / If you hate this, try

Pairs well with

  • linux-t2-headers (build out-of-tree/DKMS modules against this exact kernel — required the moment anything needs to compile a module), apple-bcm-firmware-fetcher (Wi-Fi/Bluetooth firmware — without it the kernel's wireless driver has nothing to load), apple-t2-audio-config (ALSA/UCM profiles that make the speakers work), and t2fanrd (the fan daemon — install and enable it, or the machine either roars or overheats). These four were added to the store the same day as the kernel, and together they are the complete T2 stack: kernel + headers + firmware + audio + fans.

If you hate this, try

  • linux-omarchy — Omarchy's own kernel (BORE CPU scheduler, ADIOS I/O scheduler), if you are on a normal PC and just want a faster desktop kernel. Or the stock linux kernel, if you want the plain Arch kernel with no surprises. Neither of them boots T2 hardware properly — that is the entire reason linux-t2 exists — so "hating" linux-t2 on a T2 Mac mostly means going back to macOS, not switching kernels.

Verdict: This is not a taste question — it is a hardware question. On a T2 Mac, linux-t2 is the only correct pick; the other two kernels will boot (or partly boot) a machine whose keyboard, trackpad, Wi-Fi, and audio don't work. On any non-T2 machine, linux-t2 is pointless and linux-omarchy is the interesting choice.

linux-t2 is a free alternative to replacing your 2018–2020 Intel Mac

linux-t2 is a free alternative to replacing your 2018–2020 Intel Mac. Apple stopped shipping new macOS versions for these machines, and the trade-in value of a 2019 MacBook Pro doesn't buy much — but the hardware itself (Retina display, keyboard, trackpad, speakers) is still good. linux-t2 + Omarchy keeps it a daily-usable machine for $0. What you give up, honestly: Touch ID (no Linux support, full stop), the macOS app ecosystem, and Apple's warranty/support path — plus the setup effort of lowering Secure Boot and installing four companion packages. What you keep: the machine, the display, the speakers, and a current, updating OS with years of life left in it. The honest trade-off is that this is a project, not a product: expect an afternoon of setup and a few things that need the wiki, not a ten-minute install.

Frequently asked questions

Does linux-t2 work on Omarchy?

Yes — it's in the official Omarchy repository as linux-t2 (version 1:7.2.15.arch1-1, added to the store Nov 16, 2026) and installs with one command: omarchy pkg add linux-t2. But it only makes sense on an Intel Mac with a T2 security chip (2018–2020 models). On a regular PC it does nothing the stock kernel doesn't.

Is linux-t2 really free?

Yes. GPL-2.0-only, no paid tier, no account. It's a community-patched kernel from the t2linux project, packaged for Arch by the linux-t2-arch maintainer. The Omarchy package is a 164.1 MB download, 164.1 MB installed.

Do I still need macOS installed?

For the install itself, the wiki's Arch guide assumes you partition from macOS and keep the EFI partition — and the Wi-Fi firmware fetcher extracts firmware from a macOS install. Keep a macOS partition around if you can; at minimum keep macOS Recovery reachable (hold Command+R at boot) so you can get back into Startup Security Utility if Secure Boot ever needs changing again. (Unverified: whether the fetcher works without a macOS partition present.)

Why is there no Wi-Fi after installing linux-t2?

Because the kernel doesn't ship Apple's proprietary Broadcom firmware. Install apple-bcm-firmware-fetcher from the store, run it, and reboot — the firmware lands in /lib/firmware/brcm/ and the brcmfmac driver picks it up. This is the single most common "linux-t2 doesn't work" report, and it's a missing firmware package, not a kernel bug.

Does Touch ID work?

No. There is no Linux support for Touch ID on T2 Macs. The Touch Bar itself works (function keys by default; tiny-dfr customises it but isn't in the store), the keyboard and trackpad work, but fingerprint login is unavailable.

How do I update linux-t2?

On Omarchy, omarchy-update upgrades it with the rest of the system, then reboot — you keep running the old kernel until you do. Check uname -r after rebooting to confirm the new version is live. If you build DKMS modules, keep linux-t2-headers installed so they rebuild against the new kernel.

Can I go back to the stock kernel?

Yes — that's why you keep it installed. Reboot, pick the stock linux entry in the bootloader, and once you're booted on it, remove linux-t2 with omarchy pkg drop linux-t2. Don't remove the stock kernel while linux-t2 is the only working one.
