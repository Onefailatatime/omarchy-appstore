DeepSeek Harness on Omarchy

DeepSeek Harness (dsh) on Omarchy is DeepSeek’s open-source agent runtime: the chassis that turns any language model, including a local one, into a coding agent that reads and edits files, runs shell commands, and delegates to subagents.

TL;DR

omarchy pkg add deepseek-dsh
dsh web

That installs DeepSeek Harness (v0.2.2rc.5-1, ~135.2 MB download, ~559.2 MB installed). Then open the web UI at http://127.0.0.1:3080, add your DeepSeek API key in Settings, and start a task. Note: despite the store calling it a “terminal coding agent,” dsh has no terminal UI. It runs a local web UI in your browser, plus a headless mode for one-shot tasks. It takes about 2 minutes plus API key setup.

Getting started (5 minutes)

1. Launch the web UI.

Run dsh web from your project directory. It serves the UI at http://127.0.0.1:3080 and opens your browser to it (pass --no-open if you would rather it did not). This is the main way you use dsh; there is no full-screen terminal interface like Claude Code or agy.

2. Add your API key.

Open Settings, then Models, and enter your DeepSeek API key on the DeepSeek provider card and save. The key is stored in $DSH_HOME/.credentials.yaml (default ~/.dsh), kept separate from the main settings file, which only holds a reference to it. Never paste the key itself into settings.yaml; reference it by environment variable name with apiKeyEnv if you configure it by hand.

3. Three things worth doing in the first session:

  • Pick the right preset. dsh ships four agent presets, each loading a different set of plugins. Standard is the default full coding agent: file editing, shell, search, planning, goals, subagents, and workflows. Minimal loads only a persistent bash plus a file editor, which is what DeepSeek used for its Terminal-Bench runs.
  • Know the approval flow. The web UI asks before operations that require approval under the active permission policy. File writes and shell commands surface as prompts rather than executing silently, so watch for them on your first task.
  • Remember it is a preview. The README warns, verbatim: “THERE WILL BE COMPATIBILITY-BREAKING CHANGES.” Config field names and behavior can change between releases, so pin the version you tested with and read the changelog before updating.

4. Config location.

Everything lives under $DSH_HOME, which defaults to ~/.dsh. Settings live in $DSH_HOME/settings.yaml, credentials in $DSH_HOME/.credentials.yaml, and profiles under $DSH_HOME/profiles/<name>. Set DSH_HOME to move it, which is worth doing so tests do not mix with your normal use.

Common issues & fixes

The first screen asks for a DeepSeek key and lists “No models available”

No provider is configured yet. (dsh model-error guide; DeepInfra review.)

Fix: Open Settings, then Models, enter your DeepSeek API key on the provider card, and save. If you use a custom endpoint instead, add it as a custom provider with a lowercase provider ID, a base URL, an API protocol, and at least one model, then use Fetch available models to list what it offers.

Requests fail with MISSING_CREDENTIAL or a 401

Read the error keyword first. MISSING_CREDENTIAL means the key was not saved on the model page, or the environment variable was not injected before starting dsh. A 401 on Fetch available models means the key is wrong, or the service has no GET /models endpoint, in which case enter model IDs manually and make sure they match the provider’s actual model field exactly. (dsh model-error guide.)

Fix: Keys live in $DSH_HOME/.credentials.yaml, never in settings.yaml. Re-save the key on the model page, or fix the environment variable and restart dsh.

Requests fail with UNKNOWN_MODEL, or the model selector shows “Select model” and blocks input

The requested model is not among your configured providers. (dsh model-error guide.)

Fix: Check settings.yaml under $DSH_HOME and confirm the provider and model ID are spelled exactly as the provider lists them. Model config changes take effect on the next request without a restart, so fix the file and retry.

ollama launch dsh opens a web UI that asks for a DeepSeek key and shows no Ollama models

Known bug, not your setup. The Ollama launcher writes its model list into ~/.ollama/launch/dsh/settings.yaml, but dsh dropped the file-backed settings provider that honored that path back in the 0.1 line, so no Ollama route ever loads. The break was reported to Ollama as issue 18699, closed as not planned in September 2026, and it still reproduces with current releases. (ComputingForGeeks, Nov 2026.)

Fix: Declare the Ollama route yourself in ~/.dsh/cordis.patch.yml, point its apiKeyEnv at OLLAMA_LAUNCH_DSH_API_KEY, and pin Ollama’s context length to the window you declare.

A small local model writes junk files or loops for minutes

The harness is only as good as the model under it. Small models with short context windows are the usual cause. (jacar.es local-model guide.)

Fix: Declare a contextWindow in your provider config that matches what your server actually offers, and prefer a larger model for real coding work. One tester found a 4B model completed a real task in 4 of 5 attempts, but runs took 3 to 25 minutes.

Pairs well with / If you hate this, try

Pairs well with

  • Ollama or llama.cpp for local models (no API bill, full privacy), a DeepSeek API key for the default V4 experience, and git so every agent edit is reviewable and revertible.

If you hate this, try

  • Claude Code or Antigravity CLI (agy) for a true terminal interface. Both are covered in their own guides on this site. If you hate the preview-stage rough edges, wait for a stable release; dsh is explicitly a developer preview.

DeepSeek Harness is a free alternative to Claude Code ($20/mo Pro)

dsh is MIT licensed and free, and it is the only agent in this set that is both open source and model-agnostic: it accepts DeepSeek, Anthropic, OpenAI, Bedrock, Azure, and any OpenAI-compatible endpoint, including a local llama.cpp or Ollama server. That makes it a genuine free alternative to Claude Code and Codex for the harness itself: the agent runtime costs $0; you pay only for the model you choose, and a local model costs nothing but electricity. What you give up: the polish of a finished product. It is a developer preview with breaking changes, no terminal UI, and setup that expects you to understand providers and config files. What you keep: the full agent loop, subagents, MCP support, and the freedom to swap models without swapping tools.

How to switch from Claude Code (~15 minutes)

  1. Export from Claude Code: dsh reads the hooks.json you already wrote for Claude Code through its hook bridges, and its subagent providers can delegate real work to an installed Claude Code CLI, so your existing setup is not wasted.
  2. Install dsh: omarchy pkg add deepseek-dsh, then dsh web, then add your DeepSeek key (or a custom provider pointing at any OpenAI-compatible endpoint) in Settings, then Models.
  3. What does not transfer: your Claude Code session history and per-project memory files do not carry over; dsh keeps its own append-only session log (Trajectory, stored as zstd-compressed JSONL) under $DSH_HOME.
  4. Time estimate: about 15 minutes for the key setup and one test task.

Frequently asked questions

Is DeepSeek Harness free?

Yes. It is MIT licensed and open source, released by DeepSeek AI on August 13, 2026. You pay only for model usage: DeepSeek API calls are billed per token, and local models cost nothing beyond your hardware.

Is it really a terminal coding agent?

Not in the way the store description suggests. It has no terminal UI. You drive it from a local web UI at http://127.0.0.1:3080, or headless with dsh --profile headless for one-shot tasks. If you want a TUI, use Claude Code, agy, or opencode instead.

What is Cordis?

The plugin framework dsh is built on. Everything is a plugin: the model adapter, the tool registry, the session log, the sandbox, and even the agent loop itself. That is why you can swap models, session storage (JSONL or SQLite), shells, and subagent providers in config instead of patching code.

What are the system requirements?

Node.js 22.19 or newer in the 22.x line, or Node.js 24 and later. The Omarchy package declares nodejs as a dependency, so the install should satisfy this. Building from source also needs pnpm, git, Python 3.8+, and tmux for some plugins.

Where does dsh keep its config?

Under $DSH_HOME, which defaults to ~/.dsh. Settings live in $DSH_HOME/settings.yaml, credentials in $DSH_HOME/.credentials.yaml, and profiles under $DSH_HOME/profiles/<name>. Set DSH_HOME to move it, which is worth doing so tests do not mix with your normal use.

Is it stable enough to rely on?

Not yet. It is a developer preview, and the README warns of compatibility-breaking changes. Treat it as a tool for experimenting and for projects where you can pin a version, not as production infrastructure.
