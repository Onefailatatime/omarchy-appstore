linux-t2-headers on Omarchy

linux-t2-headers is the build kit for the Linux-for-T2-Macs kernel — the headers and scripts you need to compile out-of-tree kernel modules (DKMS drivers and the like) against linux-t2 on a T2 Mac running Omarchy. It is a niche developer package: most T2 Mac users will never touch it directly.

TL;DR

omarchy pkg add linux-t2-headers

It takes ~2 minutes (92.2 MB download, 340.8 MB installed). You only need it if you build kernel modules — if you just run Omarchy on your T2 Mac, skip it.

Be honest about what this is: this package does nothing visible. There is no app to open, no window, no config file, no service. It drops header files and build scripts onto your disk so a compiler can build modules against your kernel. If that sentence meant nothing to you, you almost certainly don't need this package — and that's fine.

Getting started (5 minutes)

1. Confirm you're actually running the T2 kernel.

These headers are only useful if your running kernel is linux-t2. Check first:

uname -r

You should see a version string matching the linux-t2 package (1:7.2.15.arch1-1 at the time of writing — the version after the 1: epoch, e.g. 7.2.15-arch1-1-t2 style naming; confirm the exact string on your machine). If uname -r shows the stock Omarchy kernel instead, these headers are the wrong ones for the kernel you're booted into — install linux-omarchy-headers for that kernel, or boot linux-t2 (see "Common issues" below).

2. Install the headers and the kernel together.

The headers are useless without the kernel they belong to, and the kernel update and the headers update must move in lockstep:

omarchy pkg add linux-t2 linux-t2-headers

3. Verify the build directory exists.

DKMS and manual module builds look for the kernel build tree at /usr/lib/modules/$(uname -r)/build. Confirm it's there and resolves to a real directory:

ls -ld /usr/lib/modules/$(uname -r)/build
readlink -f /usr/lib/modules/$(uname -r)/build

If that path is missing or the symlink dangles, module builds will fail before they start — see the first issue below.

The 3 things you need to know:

  • Headers must match the running kernel exactly. A module is compiled against one specific kernel build. Headers for any other version — even one point release off — won't work. After every linux-t2 update, update linux-t2-headers too, then reboot into the new kernel before building anything.
  • Headers alone change nothing about your hardware. Wi-Fi, audio, the Touch Bar, and fan control come from the kernel (linux-t2) plus the firmware and config packages — not from this package. Installing the headers will not fix a broken trackpad or silent speakers.
  • You also need a compiler toolchain. The headers are just files; something has to compile against them. On Arch that means base-devel (gcc, make, and friends) plus dkms if you're using DKMS modules. The headers package itself only pulls in binutils, glibc, libelf, libgcc, openssl, pahole, xxhash, zlib, and zstd.

Config location.

There is none — this is not an app. The files it installs live under /usr/lib/modules/<kernel-version>/build. Nothing to configure, nothing to launch.

Practical notes: A concrete example of when you'd need this: you want to build a DKMS driver that isn't in the kernel — for example macbook12-spi-driver-dkms (keyboard/touchpad/Touch Bar driver for newer MacBooks, in the Omarchy store). That package ships source code, and DKMS compiles it on your machine against your running kernel. Without linux-t2-headers, that compile has no kernel headers to build against and fails immediately. With them, dkms autoinstall builds the module and it loads at boot. On Omarchy, omarchy-update upgrades the headers with the rest of the system — but remember to reboot into the new kernel before rebuilding modules. To remove the package: omarchy pkg drop linux-t2-headers (any DKMS modules already built keep working until the next kernel update, when they will fail to rebuild).

Common issues & fixes

All of these come from DKMS and kernel-headers troubleshooting guides and the t2linux wiki's kernel build docs — they are documented failure modes for this exact class of package, not guesses. Each one is still marked for on-machine confirmation in the checklist above, because none of them was reproduced on a real T2 Mac for this draft.

DKMS build fails — "missing kernel headers"

You try to build a DKMS module and get an error like ERROR: Missing kernel headers for module <name>/<version>, or the build dies on the first #include. The headers for your running kernel aren't installed, so /lib/modules/$(uname -r)/build points at a directory that doesn't exist.

Fix: Install the headers for the kernel you're actually running — for the T2 kernel, that's this package:

omarchy pkg add linux-t2-headers

Then verify the build directory resolves, and retry the build:

ls -ld /usr/lib/modules/$(uname -r)/build
sudo dkms autoinstall

If you just updated the kernel, reboot first — the headers match the new kernel, but you're still booted into the old one, and DKMS builds against the running kernel's version.

Headers and kernel versions don't match after an update

A kernel update lands, you reboot, and a DKMS module that used to build now fails — or dkms status shows the module built for the old kernel but missing for the new one. The kernel and the headers updated out of step, so the headers on disk belong to a different kernel version than the one you booted.

Fix: Update both packages together and reboot, then rebuild:

omarchy pkg add linux-t2 linux-t2-headers
# reboot into the new kernel
sudo dkms autoinstall
dkms status

dkms status lists every module with the kernels it was built for — the kernel with no line next to the module name is the one whose build failed. The general rule, from the DKMS guides: always install the headers matching your exact kernel version, using $(uname -r) for precision, and verify with ls /lib/modules/$(uname -r)/build afterwards.

You installed the headers, but you're booted into the wrong kernel

You have linux-t2-headers installed, but uname -r shows the stock Omarchy kernel (linux-omarchy), and DKMS still fails. Headers are per-kernel: linux-t2-headers only builds modules for linux-t2. A machine with several kernels installed needs the headers package for each kernel it actually boots — a DKMS module only builds for kernels whose headers are present.

Fix: Either boot the T2 kernel (pick linux-t2 in your bootloader), or install the headers for the kernel you're actually running:

uname -r
omarchy pkg add linux-omarchy-headers   # if you're on the stock Omarchy kernel

Check which kernel packages you have installed with pacman -Q | grep -E '^linux', and match the headers package to the kernel in uname -r before blaming the module.

Headers installed, but the DKMS build still fails

The build directory exists, the versions match, and the build still errors out — usually on a missing compiler or a missing tool (gcc: command not found, make: command not found, or a missing bc/pahole/libelf). The headers are only half the build environment; the t2linux wiki's own kernel-build guide lists bc kmod libelf pahole cpio perl tar xz git as required on Arch systems, and a DKMS build needs the compiler toolchain on top of that.

Fix: Install the toolchain and DKMS itself, then retry:

omarchy pkg add base-devel dkms
sudo dkms autoinstall

If the failure persists, read the first compiler error in the DKMS build log — not the summary at the bottom:

sudo grep -n -m 5 'error:' /var/lib/dkms/<module>/<version>/build/make.log

A stale entry can also be the culprit: old kernel references cause phantom errors, so if dkms status shows a module stuck on a kernel you no longer run, remove that entry (sudo dkms remove <module>/<version> --all) and rebuild.

You installed the headers expecting your T2 hardware to start working

Wi-Fi, Bluetooth, audio, or the Touch Bar still don't work after installing linux-t2-headers. That's expected — this package contains no drivers, no firmware, and no hardware support of any kind. It's the build kit for the kernel, not the kernel.

Fix: Install the pieces that actually drive the hardware: the kernel itself (omarchy pkg add linux-t2), then the sibling T2 packages — apple-bcm-firmware-fetcher pulls Wi-Fi/Bluetooth firmware from your on-disk macOS volume, apple-t2-audio-config supplies the ALSA config for the t2bce audio driver, and t2fanrd runs the fans. The t2linux wiki is explicit that distro-specific guides are the right path and that hardware support comes from the patched kernel plus those firmware/config packages, pre-installed in the distro ISOs. Headers only matter once you want to compile something extra on top.

Installing this package is the free, instant alternative to compiling the T2 kernel yourself

There is no paid product here to replace — the headers are free, and so is every alternative. The honest comparison is against the do-it-yourself route: installing this package is the free, instant alternative to compiling the T2 kernel yourself. The t2linux wiki's kernel guide has you cloning t2linux/linux-t2-patches, downloading the kernel source from kernel.org, applying the patches, configuring with make olddefconfig, and building with make -j$(nproc) — a 2–3 hour build needing ~20 GB of disk, plus the bc kmod libelf pahole cpio perl tar xz git prerequisites. The prebuilt linux-t2 + linux-t2-headers pair gives you the same patched kernel and the same build tree in one ~2 minute install. What you give up: the ability to tweak the kernel config before building (custom options, extra drivers built in). What you keep: a working T2 kernel and a build tree DKMS can compile against. If you later decide you do need a custom config, the headers package is still the starting point — you build against it, you don't replace it.

Frequently asked questions

Do I need linux-t2-headers if I just run Omarchy on a T2 Mac?

No. You only need it if you build kernel modules — DKMS drivers, out-of-tree modules, or your own module code. Normal use, including Wi-Fi, audio, and the Touch Bar, works (or doesn't) based on the linux-t2 kernel and the firmware/config packages, not the headers. If nobody has ever asked you to "install the kernel headers," don't install them: 340.8 MB of disk for a package you'll never use.

What does this package actually install?

The C header files and build scripts for the linux-t2 kernel, landing in the kernel build tree at /usr/lib/modules/<kernel-version>/build (confirm the exact path on a real install — see the checklist). It also pulls in 9 dependencies: binutils, glibc, libelf, libgcc, openssl, pahole, xxhash, zlib, and zstd. There is no binary to run, no desktop entry, and no config file.

Do I need to reboot after installing it?

Not for the headers alone. But if you also updated the linux-t2 kernel, reboot into the new kernel before building anything — DKMS builds against the running kernel, and headers for a kernel you haven't booted yet won't help.

Can I install headers for more than one kernel?

Yes — and you should, if you boot more than one kernel. Each kernel needs its own headers package (linux-t2-headers for linux-t2, linux-omarchy-headers for linux-omarchy). DKMS builds a module separately for every kernel whose headers are present.

How do I uninstall it?

omarchy pkg drop linux-t2-headers. Modules you already built keep working until the next kernel update, when DKMS will fail to rebuild them without the headers.

Is linux-t2-headers free?

Yes. GPL-2.0-only, no paid tier, no account. The Omarchy package is a 92.2 MB download and 340.8 MB installed.

Where does the T2 kernel itself come from?

The T2 patches come from the community t2linux project (t2linux/linux-t2-patches on GitHub, plus the wiki at wiki.t2linux.org); the Arch T2 kernel packaging is maintained at NoaHimesaka1873/linux-t2-arch. One correction worth flagging: the store catalog lists the homepage as github.com/archlinux/linux, and github.com/t2linux/linux (sometimes cited as the upstream) returns a 404 — the checklist asks Jessyka to confirm which repo the store intends.
