Muse Code on Omarchy

Muse Code on Omarchy is Meta's terminal coding agent, powered by the Muse Spark models: multi-agent by default, with subagents, an audit log, and a sandbox on from the first run.

TL;DR

omarchy pkg add muse-code

Then cd ~/my-project and run muse. That installs Muse Code (version 1.4.25.r9361.1-1, 160.2 MB download, 468.8 MB installed). On first launch, log in through your browser at dev.meta.ai. Then describe what you want done. Note: login requires a Meta account with a payment method on file.

Getting started (5 minutes)

1. Log in.

Run muse login or just muse and follow the browser prompt to authenticate at dev.meta.ai. You can also log in with a Meta Model API key by setting the META_API_KEY environment variable. If login fails with a payment-method error, see the first issue below. Sign out any time with muse logout.

2. Start with a read-only task.

Change into a project directory and run muse. On first launch in an unfamiliar directory it asks whether to trust the workspace: say yes for your own code, no for code you do not trust. Then try: "Take a look at this project and explain its main directories." Muse reads and searches the project before answering, so you see how it works before it edits anything.

3. Three things worth doing in the first session:

  • Learn the approval modes. Muse asks before it writes files or runs commands. The default is Auto-review, where an automated judge approves routine actions, and you can switch to Ask me (approve everything yourself), Plan first, or Unrestricted. Start strict and loosen up only when you trust the setup.
  • Use the built-in skills. Muse Code ships with skills like /plan (structured planning), /grill (plan validation), and /goal (objective tracking). Type /plan before a big change and let it lay out the steps first.
  • Know where the config lives. User settings are in ~/.config/muse/settings.json, login state in ~/.config/muse/auth.json, and project instructions in AGENTS.md at the project root (CLAUDE.md works as a fallback). Project memory lives in .agents/memory/: personal memory stays private on your machine, committed memory is shared with anyone who clones the repo.

Common issues & fixes

Login ends with "Muse Code requires a payment method"

Login ends with "Muse Code requires a payment method, subscribe at accountscenter.meta.com/muse_code, then log in again."

Fix: A Meta account alone is not enough: Muse Code needs a payment method on file before it will log you in. Add one at the accounts center link in the error message, then run muse login again. If you would rather not hand Meta a card, use a Meta Model API key instead by setting META_API_KEY, which counts as a login. (Fezu docs)

Muse says its sandbox cannot run on this computer, so it runs at Full only

On Linux the sandbox needs bubblewrap installed and user namespaces turned on.

Fix: The error message names the reason: either "bubblewrap is not installed" or "user namespaces are turned off". Install bubblewrap with your package manager and make sure user namespaces are enabled, then restart Muse. Until the sandbox works, Muse runs at Full, which means it executes without the containment the sandbox provides, so be extra careful about what you approve. (Fezu docs)

MCP servers are configured but the agent cannot call their tools

This is a known upstream gap in some setups: Muse can drop the returned MCP tool namespace before matching a call, so the tools never become callable.

Fix: The issue has been reported against the Muse CLI itself, and it affects frontends that drive Muse over its session protocol. Check that your servers are listed with /mcp first: if they show up but calls fail, the problem is upstream, not your config. Keep the servers in ~/.config/muse/settings.json and retry after updating Muse to the latest version. (Paseo docs)

You are on the free contributor tier and worried Meta trains on your code

Subscriptions default to the contributor tier, where Meta may use prompts and outputs to train future models, and the tier choice applies to Muse Code usage. You get a notice before your first request.

Fix: That worry is correct. To opt out, switch to the standard Model API tier, where prompts and outputs are not used for training, at standard pay-as-you-go rates. Check the current tier and pricing in your Meta account settings before sending proprietary code through it. (Muse Code vs Warp comparison)

You need to report a bug or read the source, and there is no GitHub repo for the CLI

The CLI is closed source: Meta ships it as a binary through its install scripts and has not published the source, and there is no public issue tracker for it.

Fix: The Muse Code SDK is public (github.com/meta-models/muse-code-sdk), but that is the SDK, not the CLI. For CLI problems, use Meta's official support channels and the release notes, and check the docs at dev.meta.ai first. (Muse Code FAQ)

Pairs well with

  • git (review diffs before committing), muse exec for headless or CI runs, and a second agent such as Kimi Code CLI for cross-checking a tricky change.

If you hate this, try

  • kimi-code (Kimi Code CLI) — MIT licensed with a free CLI and a free membership tier, or Claude Code as the paid reference point. If you want local models with no account at all, Kilo Code CLI can run Ollama models — if you hate the closed source and the Meta account.

Muse Code is a free alternative to Claude Code (Pro $20/mo)

Muse Code is a free alternative to Claude Code (Pro $20/mo). What you give up: Claude's models, an open-source CLI, and a public issue tracker. What you keep: a full agentic loop, subagents, MCP, hooks, skills, a sandbox, and a free tier to start on.

The honest pricing picture has two paths. The contributor tier is free to start, with rate limiting by tokens in a rolling 5-hour window, but Meta may train on your prompts and outputs. The standard Model API tier does not train on your data and bills pay-as-you-go: $0.15 per million cached input tokens, $1.25 per million input tokens, $4.25 per million output tokens. Paid plans run $5, $15, $50, and $200 per month. Check current pricing at dev.meta.ai before deciding, and pick the standard tier before sending proprietary code through it.

How to switch from Claude Code (~15 minutes per project)

  1. Export from Claude Code: your project instructions already live in CLAUDE.md. Muse Code reads AGENTS.md first and CLAUDE.md as a fallback, so your instructions work as-is, or copy them into AGENTS.md for the canonical path.
  2. Import into Muse Code: move MCP servers into ~/.config/muse/settings.json, and skills into the skills directory Muse reads. Your git history, tests, and project layout need no changes at all.
  3. What doesn't transfer: chat history, Claude-specific slash commands and permission modes (Muse has its own approval modes and built-in skills like /plan, /grill, and /goal), and Claude Code's GitHub Actions integration.
  4. Time estimate: takes about 15 minutes per project.

Frequently asked questions

Is Muse Code free?

It starts free on the contributor tier, with token rate limits in a rolling 5-hour window. Paid plans run $5, $15, $50, and $200 per month, and the standard Model API tier bills pay-as-you-go. Login requires a Meta account with a payment method on file.

What model does Muse Code run?

Muse Spark, Meta's coding model. It launched on Muse Spark 1.2 in August 2026, moved to 1.3 on September 2, 2026, and Muse Wonder and Muse Wonder Full were added October 12, 2026. The Omarchy package version is 1.4.25.r9361.1-1.

Is Muse Code open source?

No. Meta ships the CLI as a closed-source binary and has not published the source. The Muse Code SDK is public, but that is a separate package for building on the platform.

What command do I run to start it?

muse, in any project directory. muse login handles authentication, muse logout signs out, and muse exec runs a single prompt headless for scripts and CI.

Where does Muse Code store its config?

User settings in ~/.config/muse/settings.json, login state in ~/.config/muse/auth.json, project instructions in AGENTS.md (or CLAUDE.md as a fallback), and project memory in .agents/memory/.

Does Muse Code work offline or run a model locally?

No. Every prompt goes to Meta's hosted models over the network. There is no bundled local model.

Does it support MCP servers?

Yes, MCP servers are configured in settings and listed with /mcp, but there is a known upstream issue where the agent can fail to call MCP tools in some setups. See the issue above.
